# 공연 자동화 운영 반영 준비

2026-10-23 KST 사용자 확인: Last.fm API key는 발급·설정했으며 NOL 이용 허가는 아직 받지 못했다. NOL 자동 수집·저장·공개 연결은 허가 확인 전까지 보류한다. 기존 출처와 아티스트 검수는 이 보류와 별개로 계속한다.

## 현재 환경 확인

현재 `/workspace/Concert_finder` 환경의 `environment_status`는 running/current, 제한 네트워크 enforced다. Supabase 기존 연결은 ready다. 그러나 `LASTFM_API_KEY`는 runtime에 없고 현재 secret 바인딩 목록에도 없다. 다른 채팅에서 설정·검증한 키가 현재 예약 환경에 자동 전달됐다고 보지 않는다. 이 실행의 Last.fm API 요청은 0회다.

사용자가 키 값을 보내는 대신 현재 예약에 연결된 클라우드 환경 설정에서 `LASTFM_API_KEY`와 허용 도메인 `ws.audioscrobbler.com`을 반영해야 한다. 반영 후 현재 환경의 ready와 실제 API 응답을 확인한다. 이는 인기 지표/후보 발굴에만 영향을 주며 기존 DB 검수 중단 사유가 아니다.

## 준비한 수집기 수정

기존 `runSource`는 실패를 모두 `COLLECTION_OR_UPLOAD_FAILED`로 저장하고 명확한 HTTP400·설정 오류도 최대3회 수집을 재시도했다. 따라서 후보0의 전체 실패가 발생하면 운영 DB의 오류 집계만으로 원인을 구분하기 어려웠다.

- HTTP 상태, 설정 누락, robots 거부, 목록 예산 초과, 응답 크기 초과, timeout, 업로드 실패를 고정 코드로 기록한다. 알 수 없는 오류는 원문/키 포함 URL을 출력하지 않고 기존 일반 코드로 보존한다.
- 명확한 HTTP4xx(429 제외)·설정/robots/예산/크기 오류는 수집을 다시 시작하지 않는다. 429/5xx/timeout과 미분류 일시 오류는 기존 최대3회 범위를 유지한다.
- 기존 source lease와 run token을 유지한다. 업로드 실패를 수집 실패와 구분하며 다른 run을 만들거나 수집을 다시 시작하지 않는다. 실제 업로드 재전송은 기존 동일 token 경로를 유지한다.
- KOPIS의 상세 HTTP400 3회 후 중단 동작과 회당 상세100건 상한은 바꾸지 않는다. 이 수정은 HTTP400의 외부 원인을 해결하거나 빠진 후보를 확보했다는 증거가 아니다.

현재 수정은 로컬 코드/격리 검증이며 운영 배포, 수집 재실행, 공개 ON, 알림 발송은 수행하지 않았다. 기존 운영 RPC의 failure_code 문자열 계약을 사용하므로 새 DDL/권한은 필요하지 않다.

## 운영에 연결할 순서

1. 현재 환경 Last.fm 바인딩 반영 후 API 읽기 응답 확인. NOL은 허가 미확인 상태를 유지한다.
2. 수집기 수정본 검증·검토 후 별도 운영 반영 승인을 받는다. 기존 GitHub 실행기와 별도 KOPIS 실행기가 같은 수정본을 사용하는지 각각 확인한다. 새 스케줄러를 만들지 않는다.
3. 다음 기존 서버 실행의 고정 오류 코드·후보 수·source lease와 재조회 결과를 확인해 상세 HTTP400/업로드 실패/시간당 일정 지연의 실제 원인을 좁힌다. 실패 원인별 수정·격리 검증을 수행한다.
4. 아티스트 신원·승인·검색, 공식 발표/일반·선예매 절대시각/회차와 이용 조건을 충족한 출처부터 검증한다. 검증 통과 시에만 수동 공개 OFF 해제 승인을 요청한다. NOL 미허가·미확인 예매 시각을 우회하지 않는다.
5. 초기 채움 무알림·수동 차단·취소/중요 변경·기존 찜/동의를 지키며 기존 매분 워커의 서버 수락/발송 결과를 확인한다. 실제 기기 수신은 관측 또는 사용자 확인과 구분한다.

## 검증

`automated-catalog`, `kopis`, `collection` 격리 테스트와 lint/build를 실행했다. 영구 오류 요청 중단, 일시 오류의 제한 재시도, 같은 lease/token 보존, 미분류 오류의 비밀 URL 제거, 업로드 실패 시 재수집 없음과 기존 공개 보호를 확인한다. build의 기존 큰 번들 경고는 남아 있다. 실제 운영 수집/배포·공개·발송 성공은 이 검증에 포함되지 않는다.
