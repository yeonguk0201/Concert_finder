# 공연 자동화 운영 반영 준비

## 현재 출시 방침 — 2026-10-28 KST

사용자 승인에 따라 **NOL 이용허가를 전체 출시 전제조건에서 제외**한다. NOL 수집을 허가받은 것으로 해석하지 않는다. `reissue_nol`은 이번 출시 범위에서 선택 제외하며, 독립적으로 이용 조건과 공연 근거를 확인한 출처부터 자동 공개를 준비한다. 아래 10월23일 환경·운영 기록은 과거 관측이며 현재 복구 환경의 키/코드 상태로 재사용하지 않는다.

이번 사용자 지시는 검증을 통과한 공식 출처부터 자동 공개를 진행하는 조건부 승인으로 보존한다. 같은 NOL 허가를 다시 출시 승인 조건으로 요청하지 않는다. 운영 스키마/권한 변경, 새 워커·예약 생성, 근거 없는 후보 공개나 추가 테스트 발송 권한으로 확장하지 않는다.

- 출처별 이용 조건은 해당 출처에만 적용한다. NOL 미허가가 KOPIS·주최사·아티스트 공식 공지 전체의 차단 사유가 되어서는 안 된다. 다른 출처의 허가는 NOL 자료를 전재하거나 자동 추출할 권한을 뜻하지 않는다. NOL 자료/상품 직접 링크가 필요한 후보는 이번 독립 출시에서 보류한다.
- 기본 수집 `--source=all`에서도 선택 출처 `reissue_nol`을 제외한다. 기존 일정·source lease·수집 한도와 공개 OFF는 그대로다. 명시적으로 선택하는 선택 adapter 코드는 보존하지만, 별도 이용허가·운영 검증 없이 실행하라는 지시가 아니다.
- 필요한 허용 근거는 공개 이용조건·데이터 라이선스·기존 승인 범위 등으로 확인할 수 있으며, 모든 주최사에 별도 서면허가를 받도록 일괄 요구하지 않는다. 공개 페이지나 robots 허용만으로 재사용 조건 검증을 완료했다고 세지 않는다. KOPIS API의 발견 용도 승인을 예매 시각·발표 근거·포스터 표시 승인으로 확장하지 않는다.
- `scripts/concert-publication-readiness.mjs`는 최신 DB/근거 snapshot을 **출처별**로 평가한다. 검증된 한 출처가 있고 NOL이 제외 상태면 `PARTIAL_LAUNCH_AVAILABLE`이다. `READY_FOR_ACTIVATION`은 자문 결과이며 정책 변경이나 공개 영수증이 아니다. snapshot은 1시간 이내 관측을 요구하고, 개별 후보의 원본 ID/revision과 미완료 사유를 보존한다.
- 아티스트 신원/공개 승인, 한국 장소와 개별 회차, 최초 발표, 일반/선예매 구분 및 절대시각, 원문 예매 근거의 공연 일치, 중복/중요 변경·취소·수동 차단을 계속 검사한다. API/레이아웃 검증과 실행기 호환도 출처별 조건이다. 다른 출처가 준비되지 않아도 준비된 출처의 상태를 낮추지 않는다.
- 기존 DB의 `publication_enabled`는 출처 단위다. 활성화 직전 최신 policy/revision·server source lease와 대상 검증을 대조해야 한다. 조건 미완료 후보는 공개하지 않고, 과거 예매 오픈 및 초기 채움은 무알림으로 처리한다. 기존 동의/찜/기기 권한을 만들지 않는다. 새 스케줄러나 수집 재실행을 만들지 않는다.
- 현재 별도 KOPIS 실행기는 publication ON/live_after 변경 시 중단하는 계약이다. 이 조건을 임의 제거하거나 다른 채팅의 워커를 수정하지 않고 호환 확인 전 KOPIS 공개를 보류한다. 이 판단 도구는 DB/RPC 쓰기·공연 후보 변경·배포·정책 활성화·알림을 실행하지 않는다.

실행 예시(비밀 없는 로컬 snapshot만 사용):

```sh
node scripts/concert-publication-readiness.mjs .local/concert-operations/publication-input-latest.json .local/concert-operations/publication-readiness-latest.json
```

읽기 전용 입력 조회는 `scripts/concert-publication-snapshot.sql`을 사용한다. 실제 운영 스키마에서 실행 검증했으며 개인 행·기기 endpoint/키·Vault·cron command를 읽지 않는다. 출력의 permission/adapter 인증 기본값은 미확인이다. 실제 이용 조건/레이아웃 검증 근거가 생길 때만 해당 출처의 검증 입력을 보완하며, DB 수를 읽었다는 이유로 승인값을 생성하지 않는다.

## 현재 환경 확인

현재 `/workspace/Concert_finder` 환경의 `environment_status`는 running/current, 제한 네트워크 enforced다. Supabase 기존 연결은 ready다. 그러나 `LASTFM_API_KEY`는 runtime에 없고 현재 secret 바인딩 목록에도 없다. 다른 채팅에서 설정·검증한 키가 현재 예약 환경에 자동 전달됐다고 보지 않는다. 이 실행의 Last.fm API 요청은 0회다.

사용자가 키 값을 보내는 대신 현재 예약에 연결된 클라우드 환경 설정에서 `LASTFM_API_KEY`와 허용 도메인 `ws.audioscrobbler.com`을 반영해야 한다. 반영 후 현재 환경의 ready와 실제 API 응답을 확인한다. 이는 인기 지표/후보 발굴에만 영향을 주며 기존 DB 검수 중단 사유가 아니다.

## 준비한 수집기 수정

기존 `runSource`는 실패를 모두 `COLLECTION_OR_UPLOAD_FAILED`로 저장하고 명확한 HTTP400·설정 오류도 최대3회 수집을 재시도했다. 따라서 후보0의 전체 실패가 발생하면 운영 DB의 오류 집계만으로 원인을 구분하기 어려웠다.

- HTTP 상태, 설정 누락, robots 거부, 목록 예산 초과, 응답 크기 초과, timeout, 업로드 실패를 고정 코드로 기록한다. 알 수 없는 오류는 원문/키 포함 URL을 출력하지 않고 기존 일반 코드로 보존한다.
- 명확한 HTTP4xx(429 제외)·설정/robots/예산/크기 오류는 수집을 다시 시작하지 않는다. 429/5xx/timeout과 미분류 일시 오류는 기존 최대3회 범위를 유지한다.
- 기존 source lease와 run token을 유지한다. 업로드 실패를 수집 실패와 구분하며 다른 run을 만들거나 수집을 다시 시작하지 않는다. 실제 업로드 재전송은 기존 동일 token 경로를 유지한다.
- KOPIS의 상세 HTTP400 3회 후 중단 동작과 회당 상세100건 상한은 바꾸지 않는다. 이 수정은 HTTP400의 외부 원인을 해결하거나 빠진 후보를 확보했다는 증거가 아니다.

현재 수정은 로컬 코드/격리 검증이며 운영 배포, 수집 재실행, 공개 ON, 알림 발송은 수행하지 않았다. 기존 운영 RPC의 failure_code 문자열 계약을 사용하므로 새 DDL/권한은 필요하지 않다.

## 운영에 연결할 순서

1. 현재 환경 Last.fm 바인딩 반영 후 API 읽기 응답 확인. NOL은 허가 미확인 상태를 유지한다.
2. 수집기 수정본 검증·검토 후 별도 운영 반영 승인을 받는다. 기존 GitHub 실행기와 별도 KOPIS 실행기가 같은 수정본을 사용하는지 각각 확인한다. 새 스케줄러를 만들지 않는다.
3. 다음 기존 서버 실행의 고정 오류 코드·후보 수·source lease와 재조회 결과를 확인해 상세 HTTP400/업로드 실패/시간당 일정 지연의 실제 원인을 좁힌다. 실패 원인별 수정·격리 검증을 수행한다.
4. 아티스트 신원·승인·검색, 공식 발표/일반·선예매 절대시각/회차와 이용 조건을 충족한 출처부터 검증한다. 검증 통과 시에만 수동 공개 OFF 해제 승인을 요청한다. NOL 미허가·미확인 예매 시각을 우회하지 않는다.
5. 초기 채움 무알림·수동 차단·취소/중요 변경·기존 찜/동의를 지키며 기존 매분 워커의 서버 수락/발송 결과를 확인한다. 실제 기기 수신은 관측 또는 사용자 확인과 구분한다.

## 검증

`automated-catalog`, `kopis`, `collection` 격리 테스트와 lint/build를 실행했다. 영구 오류 요청 중단, 일시 오류의 제한 재시도, 같은 lease/token 보존, 미분류 오류의 비밀 URL 제거, 업로드 실패 시 재수집 없음과 기존 공개 보호를 확인한다. build의 기존 큰 번들 경고는 남아 있다. 실제 운영 수집/배포·공개·발송 성공은 이 검증에 포함되지 않는다.
