# 베타 전 자동 수집·공개 계획

결정일: 2026-10-10 (KST). 사용자 요청으로 출처 확대와 자동 운영을 외부 사용자 테스트보다 먼저 진행한다. 아래 내용은 새 구현 기준이며 현재 제공하는 기능의 완료 기록이 아니다.

## 제품 방향

encore.는 **국내 록·해외 록·J-pop의 밴드와 록 성향 아티스트가 한국에서 여는 콘서트·록 페스티벌 및 출연 소식**을 다룬다. ‘컬러’는 서비스의 콘텐츠 정체성을 뜻하며 이번 결정으로 UI 색상을 바꾸지는 않는다.

- 국적과 장르를 별도로 관리한다. 일본 출신이라는 이유만으로 모든 가수를, 해외 출신이라는 이유만으로 모든 내한 공연을 포함하지 않는다.
- 공식 아티스트 소개·소속사·공연/페스티벌의 성격을 근거로 대상 아티스트를 분류한다. 이름이나 제목의 ‘rock’ 키워드만으로 판정하지 않는다. 장르가 불분명한 후보는 검수로 보낸다.
- 혼합 장르 페스티벌은 대상 아티스트의 출연을 기준으로 포함하고, 확인된 라인업과 출연일만 연결한다. 다른 출연자를 자동으로 록 아티스트로 분류하지 않는다.
- 공연이 아직 없어도 실제 대상 아티스트를 등록·검색·찜할 수 있다. 초기 20~30팀 조사는 세 범주를 균형 있게 다루며, 등록만으로 한국 공연이 예정됐다고 표시하지 않는다.
- 수집된 새 아티스트도 공식 식별자·이름·장르 근거로 확정할 수 있으면 별칭과 함께 자동 등록한다. 사전에 관리자가 밴드를 한 팀씩 등록해야만 수집/공개되는 구조를 해소한다. 동명이인·장르 불확실은 예외 검수로 보낸다. 기존 수동 등록 SQL은 초기 보완용이다.
- 재즈·클래식·일반 팝·아이돌 전체 공연을 모으는 종합 공연 서비스는 첫 범위에서 제외한다. 공식 근거로 록/밴드 성격이 확인되는 아티스트는 포함할 수 있다.

W21에는 국내 공연도 홈에서 발견할 수 있도록 기존 내한 전용 최신 목록을 보완하는 W11 후속 작업을 포함한다. 아티스트 국적과 콘텐츠 분류를 별도로 적용하며, 일반 공연 수집 결과에서 대상 장르만 공개 흐름에 연결한다.

W26/W27은 신규 구현 작업이다. 기존 첫 수집기·실시간 구독·푸시 구현을 재사용하며, 수동 밴드 등록 SQL만으로 W21/W26/W27을 완료하지 않는다.

## 1시간 수집 운영

- 출처별 기본 실행 간격은 **매시간 1회, 60분 이하**다. 6시간 간격을 대체한다. 접근 정책과 요청 제한을 확인하고 요청 간격·최대 페이지·타임아웃을 둔다. 이 주기를 허용하지 않는 출처는 예외를 공개하고 필수 경로의 대안 출처를 확보한다.
- 현재 GitHub Actions 수집 workflow는 `17 */6 * * *`이며 아직 변경하지 않았다. Cron 문자열만 바꾸고 운영 완료로 처리하지 않는다. 기존 Supabase Cron·서버 실행 경로의 재사용 가능성을 먼저 검증하고, 수집기의 실행 시간·네트워크·실행 한도를 확인해 실제 매시간 실행되는 경로를 선택한다.
- 출처별 예정/실제 시작·종료·마지막 성공·오류·신규/변경/중복/제외·자동 공개/검수 대기 건수를 기록한다. 일부 상세 실패는 다른 정상 후보 처리와 구분한다.
- 실패는 제한된 재시도와 지연을 적용하고 실행이 겹치면 잠금으로 중복 처리를 막는다. 두 주기 연속 성공하지 못하면 운영 오류로 알리고, 마지막 성공과 지연을 확인할 수 있게 한다.
- 시간 단위 폴링은 발표 즉시 수집이 아니다. 예정 주기·실제 실행 지연·공식 발표→수집→공개→화면/푸시의 지연을 별도로 측정하며 ‘1시간 이내 수신 보장’이라고 표현하지 않는다.

## 조건부 자동 공개

| 조건 | 공개 판단 |
| --- | --- |
| 등록된 밴드/소속사·주최사·페스티벌·예매처 공식 출처, 검증된 어댑터·허용 경로 | 자동 공개 후보. 신뢰 도메인 전체를 허용하는 방식 대신 출처/경로/어댑터별 정책 사용 |
| 한국 공연, 대상 장르·아티스트 고유 ID, 공연명·확인된 날짜/기간, 원문 URL·공식 발표 근거, 파싱 유효성 모두 충족 | 신규 공연 자동 공개. 정확한 발표 시각이 없으면 확인된 날짜 정밀도만 저장하며 수집 시각으로 대체하지 않음 |
| 장소·가격·일반 예매 시각이 원문에 없으나 나머지 필수 조건 충족 | 없는 필드는 미정으로 공개. 미정 예매의 알림·캘린더 시각을 만들지 않음 |
| 동명이인/장르/라인업 불확실, 다른 출처와 날짜·장소 충돌, 중복 여부 모호, 날짜 누락, 파싱 실패 | 자동 공개하지 않고 사유와 원문을 붙여 검수 대기 |
| 기존 공연과 같은 원문 ID/URL 또는 검증된 동일 공연 매칭 | 기존 ID 유지·동일 내용 무변경. 별개 회차·도시를 합치지 않음. 단순 제목 유사성만으로 병합하지 않음 |
| 기존 공개 공연의 날짜·예매 시각·라인업·취소 등 중요한 변경 | 첫 자동 공개 단계에서는 검수 대기. 기존 정상 데이터를 그대로 유지하고 누락만으로 취소/삭제하지 않음. W22의 명시적 변경·취소 처리와 연결 |
| 관리자 공개 중단·수정 또는 자동 공개 예외 지정 | 재수집으로 자동 재공개/덮어쓰기 금지. 관리자 해제 전까지 예외 상태 유지 |

새 아티스트의 신원이 확정되면 출처 식별자와 기존 이름/별칭을 대조해 ID를 등록·재사용하고 공연 관계까지 원자적으로 저장한다. 이름이 같다는 이유만으로 서로 다른 아티스트를 합치지 않는다. 아티스트 자동 등록 실패·매칭 불확실이면 공연도 자동 공개하지 않는다. 사전 수동 등록 없이 새 아티스트→공연 자동 공개가 가능한 실제 사례를 검증한다.

원문 출처, 수집 결과, 공개 판단 사유·버전·시각, 관리자 수정 이력을 보존한다. 자동 공개는 서버 전용 권한으로 수행하고, 일반 계정에 카탈로그 쓰기 권한을 열지 않는다. 출처별 자동 공개 중지 스위치와 공개 중단·재검수 경로를 둔다. HTML/URL은 정규화·검증하고 수집한 실행 코드를 실행하지 않는다.

알림 정책은 공개 경로와 독립적이다. 초기 데이터 채움·과거 발표 재수집은 신규 알림을 보내지 않는다. 초기 채움 종료 기준과 이후 신규 판정 기준을 명시하고, 자동 공개의 중복/재시도·관리자 재공개로 알림을 반복하지 않는다. 예매 알림은 확인된 미래 예매 시각·저장·동의·유효 기기를 모두 확인한다.

## 외부 사용자 테스트 시작 기준

- 국내 록·해외 록·J-pop 밴드 각각의 실제 수집 경로와 범위가 검증되고, 독립 운영 주체의 출처 최소 2곳이 연결됐다.
- 세 범주에서 공식 근거가 있는 실제 한국 예정 공연을 확보해 검색·찜·상세·저장에 사용한다. 범주별 확보 건수·미정 정보·누락 범위를 기록한다. 발표가 없어 확보하지 못한 범주는 그대로 표시하고 테스트 시작/공개 목표일을 재평가한다. 가상 공연으로 대신하지 않는다.
- 운영 테스트 공연·임의 라인업을 식별하고 공개 중단/정정한다. 원본을 삭제하기보다 이력을 보존하며 기존 저장 항목의 상태 안내를 확인한다. 가상 정보가 남아 있는 프리뷰는 샘플 표시를 유지한다.
- 운영 환경에서 24시간 매시간 반복 수집, 신규 자동 공개·모호 후보 검수 분기와 두 브라우저 화면 반영을 확인했다. 중복·실패·재시도·파싱 변화·출처 충돌·권한을 검증했다.
- 초기 채움 무알림, 이후 신규 대상만 한 번 수신, 관리자 예외·공개 중단 유지, 미정·과거 예매 제외를 확인했다.

이 기준에 못 미치면 W18 외부 테스트와 10/19 베타 공개를 늦춘다. 10/26 1차 완성도 조건부 목표다. 기본 기능 수동 시연이나 수집 코드 작성만으로 데이터 준비 완료를 선언하지 않는다.
