# 예약 주기를 Codex 앱으로 통합

사용자가 설정한 앱 예약은 4시간이다. 현재 운영 실행기와 DB는 각각 마지막 시작부터 5시간을 추가로 검사한다. 따라서 앱이 정상 호출해도 실행을 건너뛰는 현상이 생긴다.

사용자 추가 승인 후 2026-10-22 KST 운영 DB에 lifecycle 변경을 적용했다. 실행기와 예약 지시문을 함께 전환하여 앱이 실행 간격을 정한다. 앱의 기존 4시간 설정은 변경하지 않는다.

변경 내용:

- 로컬 대기열의 lastStartedAt 경과 시간 검사를 제거하고 이력 자체는 보존한다. 재개할 활성 batch가 있으면 그대로 반환하며 같은 40팀을 유지한다.
- 서버 실행에 finished_at을 추가하고 service_finish_integrated_review가 종료를 확인한다. 종료된 작업 뒤에는 최소 대기시간 없이 다음 예약이 실행될 수 있다.
- 미종료 실행은 기존 5시간 쓰기 임대가 살아 있는 동안 새 실행을 차단한다. 5시간은 장애 복구를 위한 임대 만료이며 예약 주기가 아니다.
- finish 응답 오류·유실 또는 키 누락 시 로컬 active를 지우지 않는다. 동일 finish 재시도는 멱등이다. 닫힌 작업의 새 쓰기·context·begin 재개는 거부하고 기존 receipt의 동일 요청 재조회는 보존한다.
- 수동 결정·버전·동일 최대 40팀·기존 dedicated runner·제공처 cooldown·캐시/근거 유효기간은 유지한다.

운영 마이그레이션은 [20261021165010_integrated_review_lifecycle.sql](../supabase/migrations/20261021165010_integrated_review_lifecycle.sql)이다. 설치된 20261020053150 마이그레이션은 수정하거나 재적용하지 않았다. 공식 MCP apply_migration으로 적용하고 원격 이력에서 생성된 버전으로 로컬 파일명을 맞췄다. CLI는 이 환경의 읽기 전용 홈 디렉터리에서 실패하여 파일 생성에 사용하지 못했다.

배포 시 한쪽 예약 일시정지 및 실제 작업 종료 확인 → 승인된 새 마이그레이션 생성/적용/검증 → 양쪽 실행기 동기화 → 새 예약 지시문 반영 → 소유권이 있는 예약만 재개한다. 로컬 코드도 함께 바뀌어야 같은 문제가 재발하지 않는다. 옛 실행기가 종료 기록을 남기지 못한 최근 실행은 기존 임대가 만료될 때까지 한 번 기다릴 수 있으며, 임의로 완료 표시하지 않는다.

검증 결과:

- PGlite에서 기존 승인·권한·관계 보존 검증과 새 lifecycle SQL을 실행해 통과했다. 종료 직후/4시간 뒤 새 실행 가능, 미종료 작업 차단, 종료 RPC 멱등, public/authenticated 권한 거부, 종료 후 새 쓰기 거부, 만료된 임대 복구를 확인했다.
- 전체 회귀 Node 137개와 Vitest 100개 통과. 마지막 CLI lifecycle 식별값 보완 후 대상 Node 19개와 lint를 다시 통과했다.
- npm run build 및 git diff --check 통과. TS/UI 파일은 변경하지 않았다. 빌드의 기존 500 kB 초과 번들 안내는 남아 있다.
- 운영에서 finished_at 컬럼, 종료 RPC 서비스 전용 권한, 기존 간격 검사 제거 및 busy 검사 존재를 재조회했다. 기존 실행을 완료 표시하거나 아티스트 상태를 바꾸지 않았다. push/PR/merge는 수행하지 않는다.

자동 승인 검토는 서비스 키가 있는 환경에서 외부 Supabase CLI를 다운로드·실행하는 요청을 거부했다. 기존 마이그레이션 작업 금지 범위도 이유로 들었다. 최초 거부 시에는 우회하지 않고 PGlite로 초안을 검증했다. 사용자 추가 승인 후 키를 전달하지 않는 환경에서 고정 버전 CLI 실행을 시도했으나 파일 시스템/명령 문제로 실패했다. 운영 DDL은 승인된 공식 MCP 경로로 적용했다.
