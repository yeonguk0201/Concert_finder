## 진행 방법

1. 운영자는 테스트 시작 전에 배포 URL·커밋과 실제 공개된 밴드·공연·예매 일정 하나를 확인한다. 미래 예매가 없으면 저장·푸시 시나리오의 제한을 기록하고 가능한 흐름만 진행한다. 운영 공연의 시각·라인업을 테스트 목적으로 바꾸거나 가상 공연을 등록하지 않는다.
2. 참여자에게 T01~T06의 목표를 하나씩 전달한다. 처음에는 조작 방법을 설명하지 않고 관찰한다. 힌트나 도움을 줬다면 기록하고 독립 성공과 구분한다.
3. 기기·OS·브라우저 버전과 아이폰 홈 화면 설치 여부를 기록한다. 같은 사람이 여러 기기를 사용해도 참여자는 한 명으로 집계한다. 초대만 받거나 응답하지 않은 사람은 완료 인원에 포함하지 않는다.
4. 단계별 결과를 성공 / 도움 후 성공 / 실패 / 미실행으로 남긴다. 확인하지 않은 항목은 성공으로 채우지 않는다. 알림·삭제의 상세 기술 검증은 기존 기기 통합 기록표를 사용한다.
5. 피드백을 재현하고 우선순위를 정한다. 수정 후 같은 순서로 다시 확인하며, 원래 참여자의 재확인 여부를 별도로 남긴다.

## 참여·실행 기록

연락처와 이메일은 Git에 기록하지 않는다. P01 같은 별칭만 사용하며 연락처 대응표가 필요하면 저장소 밖에서 별도 관리한다. 화면·로그에는 세션·푸시 구독 정보가 포함되지 않도록 확인한다.

| 참여자 별칭 | 실행일 KST | 배포 URL·커밋 | 기기·OS·브라우저 버전 / 홈 화면 여부 | T01~T07 각각의 결과·도움 여부 | 피드백 ID | 응답·재확인 상태 |
| --- | --- | --- | --- | --- | --- | --- |
| 미배정 | | | | 미실행 | | 응답 없음 |

현재 전달받아 기록한 집계: 외부 참여자 응답 0명, 핵심 시나리오 실행 기록 0명. 모집 인원은 미확인이다. 개발자 본인의 [첫 사용성 피드백 6건](user-feedback-20261010.md)을 별도 기록했으며 5~10명 외부 테스트 인원에 포함하지 않는다. 새로운 응답이 생기면 실제 근거와 함께 이 집계를 갱신한다.

기존의 “인터랙션이 충분하지 않음”, “관리자 화면 UX 개선 여지”는 구체적 화면·행동·기대 결과가 없는 선행 의견이다. 5~10명 테스트 결과나 재현 완료 오류로 집계하지 않는다. 관리자 UX는 일반 참여자 테스트와 분리하고, 관리자 권한을 배포하지 않는다.

## W18 종료 기준

- 서로 다른 실제 사용자 5~10명의 응답과 시나리오 실행 범위를 기록했다.
- 핵심 실패를 재현하고 P0/P1 수정·재검증 결과를 남겼다. 남은 오류·제약·후속 개선을 분류했다.
- 앱 변경은 관련 동작 검사와 lint/build, UI 변경은 데스크톱·모바일 확인을 마쳤다.
- [로드맵](development-roadmap.md)과 [작업 목록](development-backlog.md)에 실제 참여 인원·수정 결과·남은 작업을 반영했다.

응답 대기 중에는 자동 회귀 검증과 기존 오류 재현을 진행한다. 준비 완료나 자동 검사 통과만으로 W18 또는 베타 공개 조건을 완료 처리하지 않는다.
