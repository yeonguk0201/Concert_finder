# 사진 표시와 출처 UI 검토

상태: 목록 그래픽 사용 결정. 실제 사진을 목록에 추가하는 아래 대안들은 검토 중이며, 아직 구현하거나 최종 채택하지 않았다.

## 현재 적용

- 홈의 아티스트 목록, 검색 결과, 찜한 아티스트, 관련 아티스트에는 색상·이니셜 그래픽 아바타를 사용한다.
- 공연 목록과 추천 카드에는 공연 ID에 따라 유지되는 그래픽 배경과 공연명을 사용한다. 공식 포스터가 등록되어 있어도 목록에서는 그래픽을 표시한다.
- 공연 상세에서는 승인된 공식 포스터와 연결된 아티스트 사진 표시를 유지한다. 실제 사진이 표시되는 곳의 출처·라이선스·사진 만료 처리는 유지한다.
- 그래픽으로 표시하는 목록에서는 사진 요청이나 사진 출처 드롭다운·YouTube 채널 사진 링크를 만들지 않는다. 아티스트의 공식 사이트·영상 링크 등 다른 기능과는 별개다.
- 저장된 사진 데이터, 관리자 검수 상태와 사진 표시 권한은 변경하지 않는다. 아티스트 소개의 Wikipedia 연결은 이 결정의 범위에 포함하지 않는다.

## 향후 실제 사진을 추가한다면 고려할 방식

### 1. 사진 정보 창

위키미디어 등 사진의 상세 출처 정보를 개별 카드의 드롭다운 대신 별도 창으로 정리하는 안이다.

- 해당 카드 묶음 근처에 `사진 정보 ⓘ`를 하나 둔다.
- 누르면 해당 영역에 표시된 사진의 썸네일, 아티스트명, 촬영자, 원본 링크, 라이선스 링크와 편집 여부를 보여준다.
- 사진과 출처 항목을 명확히 대응시키고, 키보드·모바일에서도 열고 닫을 수 있게 한다.
- 사진마다 실제 라이선스와 지정된 크레딧 조건을 확인한다. 모든 위키미디어 사진이 같은 조건이거나, 정보 창 하나면 항상 충분하다고 가정하지 않는다.

### 2. 카드 묶음 아래 사진 제공 영역

YouTube 등 제공자를 카드의 클릭 영역에서 분리하는 안이다. 위치는 **사이트 맨 아래 공통 푸터가 아니라, 사진이 있는 카드 묶음 바로 아래**다.

```text
요즘, 이 아티스트

[ 아티스트 A ] [ 아티스트 B ] [ 아티스트 C ]

사진 제공: [YouTube 공식 로고] B · C       사진 정보 ⓘ
──────────────────────────────────────────────────────
다음 공연은 여기서
```

- 카드 자체에서는 아티스트 상세로 이동한다. 외부 출처 링크는 별도의 사진 제공 영역에 둔다.
- 여러 출처가 섞일 때는 어떤 사진을 YouTube에서 제공했는지 아티스트명·사진 대응으로 명확히 식별한다.
- YouTube 브랜드는 공식 자산, 최소 크기, 대비와 링크 조건을 따른다. 출처 전체를 정보 창·hover·먼 공통 푸터 안으로만 숨기는 방식은 채택하지 않는다.
- 이 배치가 실제 구성에서 제공자 표시 조건을 충족하는지 확인한 뒤 적용한다. 출처 조건이 충족된 것으로 미리 확정한 설계가 아니다.

1번과 2번을 함께 사용하는 방식도 후보로 남긴다. 사진이 없는 현재 목록에는 두 UI를 추가하지 않는다.
