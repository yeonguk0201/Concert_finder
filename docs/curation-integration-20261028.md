# 복구 작업의 dev·main 통합

2026-10-28 KST 사용자 요청에 따라 복구 브랜치의 누적 작업을 최신 dev와 통합한다. 개별 검수·감시 기록은 `docs/curation-runs/`의 해당 관측 시각 기준 자료이며 현재 운영 상태나 전체 완료를 보장하지 않는다.

## 포함한 변경

- 신규/별칭 identity CLI, 불변 요청 journal, receipt 복구, 공개 검색 readback을 기존 최대40팀/5시간 통합 검수에 연결했다. 같은 batch에서 identity 변경 후 승인은 다음 정규 batch로 미루며 별도 writer로 우회하지 않는다.
- 기존 이름·별칭 검색의 NFKC·대소문자·공백 정규화를 최신 dev의 승인된 카탈로그 검색 화면에 연결했다. 서로 다른 이름/별칭을 이어 가짜 일치를 만들지 않는다.
- 복구 후 아티스트 검수와 읽기 전용 공연 운영 감시의 출처·적용·receipt/readback·미완료 요건을 보존했다. `.local` queue·캐시·보안 바인딩은 Git에 포함하지 않는다.
- 최신 dev에 반영된 공연 전용 수집, Reissue/NOL 파서, 아티스트 연결 소실 방지, 승인 카탈로그 조회 및 관리자 전용 가져오기 경로를 보존했다.

## 마지막 실행 기록의 범위

- [R40](curation-runs/20261027-223733-artist-review-629b62a1.md): 고정40팀에서 기존 아티스트 승인4건, 95 task checkpoint와 server finish 확인. 당시 DB664팀/승인457/미검수200/제외7. 채널·사진 저장과 신규/별칭 변경은0이었다.
- R40 제공처 요청은23회이며21회만 팀별 대상이 확인된다. MusicBrainz 내부 추가 시도2회는 대상/상태 로그가 없어 미배분으로 별도 보존했다. 해당2회를 특정 팀에 임의 배분하지 않는다.
- [M28](curation-runs/20261027-232837-concert-operations.md): 이전 감시 대비 의미 있는 변화가 없어 기존 fingerprint와 마지막 통지 상태를 보존했다. 수집 공백·공연 필수 정보·공개 정책·외부 이용 허가의 미완료 조건은 해결된 것으로 세지 않았다.

## 반영 경계

PR은 작업 브랜치→dev, dev→main 순서로 진행한다. 필수 CI와 충돌 해결 결과를 확인한 뒤 병합한다. 이 통합은 운영 DDL·권한 변경·정책 공개ON·수집 수동 실행·알림 발송·예약 변경을 수행하지 않는다. NOL 서면 이용허가, 실제 공연 일반/선예매 절대시각·회차 및 기기 수신은 별도 검증 사항이다.

기존 검증 캐시와 수동 결정·미승인 초안은 보존한다. 로컬 queue를 초기화하거나 과거 packet/apply를 재전송하지 않는다.
