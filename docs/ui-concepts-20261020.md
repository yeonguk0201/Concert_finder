# UI 디자인 시안

시안 경로: 개발 서버의 `/ui-concepts/index.html`. 상단에서 세 디자인과 데스크톱·모바일 프레임을 전환한다. 기존 앱과 별도로 제공하는 비교용 프로토타입이다.

## 선택한 통합 방향: A + C

사용자가 A의 분위기에 C의 아티스트 추천과 달력을 결합한 방향을 선택했다. 기본 시안을 `combined`로 바꾸고 원본 A·B·C도 비교할 수 있도록 유지했다.

- A의 코발트 블루, 밝은 바탕, 그래픽 티켓, 공연 포스터를 유지한다.
- 히어로 아래에 ‘요즘, 이 아티스트’를 배치한다. 아티스트 영역과 공연 카드의 동일 아티스트 찜 상태를 함께 갱신한다.
- 데스크톱은 왼쪽에 아티스트와 공연, 오른쪽에 예매 달력과 티켓 오픈 목록을 둔다. 기존 C의 청록색 대신 A의 블루로 통일한다.
- 달력의 티켓 오픈일을 선택하면 해당 날짜의 예매 목록을 보여준다. ‘전체 보기’로 되돌릴 수 있다.
- 모바일은 아티스트 → 예매 일정 → 공연 순서로 배치한다. 달력은 처음에 접고 펼칠 수 있게 하며 티켓 오픈 목록은 바로 보여준다.
- 통합 시안도 가상 데이터와 화면 내 상태만 사용한다. 실제 앱 UI 적용은 아직 수행하지 않았다.

통합 시안과 기존 세 시안 모두 1440px·390px·320px에서 가로 넘침, 로그인 노출, 검색·필터·찜·상세·일정 저장을 검증했다. 통합 달력의 날짜 필터·초기화, 찜 상태 동기화, 모바일 콘텐츠 순서와 달력 펼침, 오프라인 통합 시안 기본 선택도 확인했다.

## 공통 개선

### 영상 캐러셀

영상·라이브 영역의 안내 문구와 하단 썸네일 설명을 삭제하고, ‘더보기’와 좌우 버튼으로 교체했다. 두 카드를 표시하고 버튼·키보드 화살표로 두 영상씩 이동한다. 마우스 드래그와 네이티브 터치 스와이프도 지원하며, 드래그 직후 영상 링크가 열리지 않게 한다. 양 끝과 영상 수가 적은 경우 버튼을 비활성화하고, 모션 감소 설정에서는 즉시 이동한다. 크기가 바뀌면 이동 가능 상태를 다시 계산하고 화면 교체 시 ResizeObserver를 해제한다.

더보기는 아티스트 이름과 뮤직비디오/라이브 키워드의 YouTube 검색 결과를 새 탭으로 연다. 동영상 감상 영역이므로 YouTube를 선택했고, 음악 감상 서비스로의 전환은 추가하지 않았다.

### 브라우저 코멘트 반영: 아티스트 상세 다듬기

- 동영상은 그래픽 대체 화면 위로 YouTube의 `i.ytimg.com` 썸네일을 직접 표시한다. 16:9, 지연 로딩, 원격 로딩 실패 안내를 적용했다. 이미지를 다운로드해서 복제하지 않는다. 이전의 완전 오프라인 그래픽 시안과 달리 썸네일 표시는 네트워크가 필요하다. 동영상 재생은 클릭 시 YouTube에서 진행한다.
- 소개를 하나의 본문으로 합치고 두 줄 말줄임 → 전체 펼침 → 본문 아래 접기로 바꿨다. 아티스트를 바꾸면 접힌 상태로 시작한다.
- 아티스트·공연 상세의 뒤로가기는 데스크톱에서 숨기고 모바일에만 화살표로 표시한다. 접근성 이름은 ‘이전 화면’으로 유지한다.
- 아티스트 배너는 헤더 바로 아래부터 전체 너비로 이어지며 아래쪽이 흰 배경으로 녹아든다. 배너의 다크 미리보기 버튼을 누르면 검은 배경으로 녹아드는 안을 비교할 수 있다. 운영체제의 색상 선호도도 초기값에 반영한다. 다른 페이지는 기존 밝은 시안이다.
- 공연 둘러보기의 아티스트 검색 안내 문구를 삭제했다.
- 공연 상세는 원형 프로필과 아티스트 이름을 한 버튼으로 묶어 아티스트 상세로 연결한다. 이 시안의 프로필 사진은 아직 연결하지 않아 이니셜 대체 이미지를 사용한다.

검증: 1042px·390px·320px에서 헤더와 배너의 연속 배치, 전체 너비, 소개 펼침과 하단 접기, 모바일 화살표, 밝은/어두운 배경, 실제 YouTube 썸네일 로딩(480px 원본), 썸네일 실패 대체, 프로필 링크와 원형 모양, 안내 문구 삭제를 확인했다. lint/build/diff 검사도 통과했다. 기존 앱 번들 크기 경고는 남아 있다.

### 공연 탐색·검색 분리와 아티스트 상세, 날짜별 추천

- `#discover`는 공연만 표시한다. 분류와 공연 날짜로 좁히며, 아티스트 검색은 별도 `#search` 화면으로 이동한다.
- `#search`는 검색어를 입력하고 전체·아티스트·공연 결과를 선택하는 독립 화면이다. 메인 검색과 헤더 검색 버튼도 이 화면으로 연결한다.
- `#artist`는 아티스트 배너 → 펼치는 소개 → 예정 공연 → 동영상 → 라이브 공연 영상 → 함께 발견할 아티스트 순서다. 메인 추천·검색 결과·찜 목록·공연 상세에서 아티스트를 선택할 수 있다.
- 소개·배너·썸네일은 편집·그래픽 시안이다. 월간 시청자 수나 조회 수를 임의로 표시하지 않는다. 영상은 자동 재생이나 임베드 요청 없이 클릭한 경우에만 YouTube 새 탭으로 이동한다. 확인하지 못한 라이브 영상은 빈 안내로 표시한다.
- 저장한 예매 일정 오른쪽에 캘린더만 배치하고, 기존 ‘그날의 함성까지’ 영역은 그 아래에 둔다. 모바일에서는 캘린더를 목록 위에 둔다.
- 날짜를 선택하면 저장한 **티켓 오픈일**을 기준으로 일정 목록을 바꾼다. 저장 일정이 없으면 그날 **공연일**이 일치하는 공연을 최대 3개 추천한다. 추천이 4개 이상이면 같은 공연 날짜를 유지한 채 공연 둘러보기로 이동한다. 그날 공연도 없으면 빈 안내와 전체 공연 둘러보기를 표시한다.
- 캘린더의 파란 점은 저장한 티켓 오픈일, 주황 점은 공연일이다. 이전·다음 달과 전체 일정 보기를 제공한다.

분기 체험용 가상 샘플: 2026년 10월 23일(저장한 예매 1개), 25일(저장 예매 없음·당일 공연 4개 중 3개 추천), 26일(공연 1개), 29일(예매·공연 모두 없음). 공연일과 티켓 오픈일을 섞거나 가까운 다른 날짜의 공연을 같은 날짜인 것처럼 추천하지 않는다.

### 메인 확정 후 화면 확장

메인 디자인은 A+C로 선택했으며, 동일한 디자인 언어로 다음 화면을 추가했다. 실제 서비스 코드가 아닌 별도 프로토타입이다.

| 화면 | 구성과 체험 |
| --- | --- |
| 검색 결과 | 아티스트와 공연을 나눠 표시하고 검색어·분류 필터·결과 없음 상태를 확인한다. 검색어는 HTML 이스케이프 후 출력한다. |
| 로그인 | 이메일 입력 → 인증번호 입력 → 로그인 완료 상태를 체험한다. 브라우저 입력 검증만 수행하며 인증 요청이나 메일 발송은 없다. |
| 찜한 아티스트 | 아티스트 커버와 다음 공연을 표시한다. 다른 화면의 찜 상태와 연동하며 빈 목록과 샘플 복원을 제공한다. |
| 내 예매 일정 | 티켓 오픈일 중심의 목록과 저장 해제·빈 목록·샘플 복원을 제공한다. 알림 예약으로 표현하지 않는다. |
| 공연 상세 | 큰 포스터, 공연 정보, 아티스트 찜과 예매 일정 저장을 제공한다. 저장 상태는 일정 목록에도 반영된다. |

메인 검색·상단 메뉴·모바일 하단 메뉴·시안 바로가기에서 이동한다. 파일 URL에 `#search`, `#artists`, `#saved`, `#detail`, `#login`을 붙이면 해당 화면으로 진입할 수 있다. 페이지 이동 시 제목으로 초점을 이동하고 로그인 다이얼로그는 Escape로 닫을 수 있다. 찜과 일정은 화면을 이동해도 유지되지만 새로고침하면 초기화된다. 초기 샘플은 아티스트 2팀과 예매 일정 2개이다.

오프라인 파일 재생성:

```powershell
node scripts/package-ui-concepts.mjs <출력 폴더>
```

UTF-8로 오프라인 HTML을 생성한다. `encore-combined.html`과 새 전달 파일 `encore-page-flow.html`은 동일한 전체 화면 흐름이며, `encore-ui-studio.html`은 원본 디자인 비교와 전체 화면 흐름을 포함한다.

검증: 1440px·390px·320px에서 10개 화면 상태의 가로 넘침과 브라우저 오류가 없고, 검색·분류·빈 결과·찜 동기화·저장 동기화·달력·이메일/인증번호 체험·로그아웃을 확인했다. 화면별 직접 링크와 비교 페이지의 임베드 전환도 확인했다. 실제 계정·이메일·공식 공연 DB·푸시는 연결하지 않는다.

- 로그인 진입점을 설정 메뉴 대신 상단 오른쪽의 명시적인 버튼으로 표시한다. 모바일에서도 첫 화면에 유지한다.
- 검색, 공연 분류, 아티스트 찜, 공연 상세, 일정 저장을 체험할 수 있다.
- 계정 연결·메일 발송·영구 저장 없이 화면 상태만 바뀐다. 새로고침하면 초기화된다.
- 공연·일정·인기도는 가상 샘플이며 모든 시안에 안내를 표시한다. 일정 저장을 푸시 알림 예약으로 표현하지 않는다.
- 외부 이미지·폰트·서비스 요청 없이 시스템 한글 글꼴과 CSS 그래픽으로 구성한다.

## 디자인 방향과 토큰

| 시안 | 색상 | 구성 | 타이포그래피와 의도 |
| --- | --- | --- | --- |
| A. 포스터 월 | 바탕 `#FAFBFC`, 잉크 `#19263B`, 코발트 `#244FE8`, 연파랑 `#EAF0FF`, 티켓 스티커 `#D4EC78` | 왼쪽 헤드라인·검색 / 오른쪽 그래픽 티켓 → 공연 포스터 4열 | 시스템 한글 산세리프 + Arial의 굵은 티켓 활자. 밝고 가벼운 탐색을 우선한다. |

공통 구조는 왼쪽 정렬을 기준으로 한다. A와 B가 단순한 색상 변형에 머무르지 않도록 A는 열린 검색형 히어로, B는 무대형 히어로와 별도 검색 줄로 구분했다. C는 아티스트와 달력 중심의 정보 구조를 사용한다. 모바일은 단일 열로 재배치하고 공연 목록은 2열로 유지한다.

## 검증

- `npm run lint` 통과.
- `npm run build` 통과. 기존 앱 번들 크기 경고는 남아 있다.
- `node --check`로 두 JavaScript 파일 구문 확인.
- 로컬 Edge의 임시 프로필에서 각 시안의 1440px, 390px, 320px 화면 확인: 가로 넘침 없음, 상단 로그인 노출, 브라우저 오류 없음.
- 로그인 시안 열기·닫기, 메일 미발송 안내, 검색·빈 결과, 분류 필터, 찜, 상세, 재진입 시 일정 저장 상태 확인.
- 비교 페이지의 시안 전환과 390px 모바일 프레임 전환 확인. 별도 산출물 폴더의 단일 HTML 파일에서도 오프라인 시안 전환 확인.
- 외부 네트워크 요청 없음 확인. 실제 로그인·공연 데이터·푸시 기능은 이 시안 검증 범위에 포함하지 않는다.

현재 체크아웃이 로컬 `dev`보다 164개 커밋 앞서 있어 최신 작업을 보존한 채 `codex/feat-ui-design-concepts`로 분기했다. 푸시와 PR 생성은 수행하지 않는다.
