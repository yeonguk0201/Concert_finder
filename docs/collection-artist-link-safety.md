# 공연 수집기의 아티스트 연결 보호

공용 `scripts/collect-catalog.mjs` 경로를 보완한다. 최신 dev의 `--concerts-only`와 Reissue/NOL 경로·adapter version·KOPIS 비밀 없는 요청 진단을 보존한다. 공연 전용 및 Reissue/NOL 업로드의 `identities=[]`를 유지하며 Reissue/NOL에는 아티스트 보완을 새로 연결하지 않는다. 운영 배포·workflow/예약 변경·수집 재실행은 수행하지 않았다. 별도 채팅의 KOPIS 전용 실행기는 이 변경을 자동으로 전달받지 않는다.

## 현재 DB 신원 대조

업로드 실행은 source lease 안에서 최신 bands의 id/name/aliases/country_code/musicbrainz_id/curation_status만 안정된 ID 순서로 페이지 조회한다. 승인된 이름만 읽으면 동명이인 충돌을 숨길 수 있으므로 held/excluded/unreviewed도 충돌 검사에 포함한다. 사용자 정보·키·원본 API 응답은 읽거나 출력하지 않는다. 조회 오류·중복 ID·페이지 상한은 연결 문맥 미확인으로 중단한다.

기존 정적 출처 매칭 이후 아직 key 없는 출연진에 현재 DB를 대조한다. 유일한 승인 아티스트의 검증된 별칭이면 DB의 정식 이름으로 MusicBrainz를 조회한다. 제공처 결과가 정확히 하나이고 잘림이 없으며 DB와 MBID·국가까지 일치해야 연결한다. 이름만 보고 mb key를 생성하거나 기존 후보의 key를 복원하지 않는다. DB 중복 이름·보호 상태·신원 충돌은 명시적 검수 사유다. 알려지지 않은 이름은 기존 제공처 검색/미검수 후보 경로를 유지한다. 기존 정적 key는 이 보완에서 새로 해석하거나 승인하지 않는다.

같은 제공처 조회 한도에서 승인 카탈로그 출연진을 먼저 처리한다. 원래 후보·출연진 순서는 바꾸지 않는다. 여러 언어 별칭은 같은 정식 이름의 기존 7일 캐시를 공유한다. 조회 한도25·속도 제한·실패 중단 기준을 늘리거나 MusicBrainz 차단을 우회하지 않는다. 외부 조회 생략 모드는 신원을 추정하지 않고 미확인 사유를 남긴다.

## 빈 연결 덮어쓰기 차단

각 `service_complete_collection` 시도 직전에 이번 source의 candidate URL을 최대20개씩 묶어 기존 artist_keys/band_ids만 조회한다. 기존 key가 하나라도 새 입력에서 빠지거나, 저장된 band_ids에 대응할 key가 부족하면 `COLLECTION_IDENTITY_REGRESSION`으로 해당 source 완료를 차단한다. 빈 값뿐 아니라 부분 소실·신원 교체도 검수 대상이다. 읽기가 실패하면 `COLLECTION_LINK_CONTEXT_UNAVAILABLE`로 중단한다. `--skip-artist-lookup`에도 같은 검사를 적용한다.

과거 연결은 검증 완료 여부가 보장되지 않으므로 새 payload로 복사하지 않는다. 실제 출연진 변경·취소와 일시 조회 실패를 구분할 근거가 필요하다. 새 후보 초안과 대상 URL/기존·새 key 수/검수 사유는 출력 보고서의 `identity_link_review`에 보존한다. 기존 source lease는 `service_fail_collection`의 고정 실패 코드로 종료하며 성공/완료로 세지 않는다. 다른 source는 기존 루프에서 계속 진행할 수 있지만 차단된 source의 부분 업로드는 하지 않는다. 이 보수적 차단은 해당 source의 다른 후보 갱신도 검수 해결 전까지 미룰 수 있다.

검수자는 기존 연결이 맞았는지, 공식 출연진이 교체됐는지, 취소·주요 변경인지 확인해야 한다. 이 코드는 수동 연결 수정·과거 apply/수집 재전송·공개 ON·알림 발송을 수행하지 않는다.

## 적용 범위와 한계

이 보호는 공용 클라이언트 경로에 있다. 운영 SQL `admin_ingest_catalog`의 upsert 자체는 변경하지 않았으므로 다른 writer나 조회 직후의 동시 관리자 변경까지 원자적으로 보호하지 않는다. 기존 source lease는 유지하지만 전역 관리자 잠금으로 간주하지 않는다. 모든 writer를 원자적으로 보호하려면 별도 서버 계약 변경·운영 승인·격리 DB 검증이 필요하다. 현재 코드를 다른 실행기에 자동 배포하거나 운영 DDL을 적용하지 않았다.

DB에서 이미 소실된 연결, 신원 미검수, 제공처 장애, NOL 이용허가, publication OFF, 정확한 예매 시각 등은 자동으로 해결되지 않는다. 연결 보호 코드의 통과를 공연 공개·발송 성공으로 세지 않는다.

검증은 관련 실행 기록을 따른다. 운영 읽기 전용 검사에서 현재 카탈로그640팀/승인208팀을 읽고 동일 연결 입력 통과 및 빈 연결 가상 입력 차단을 확인했다. 이 검사는 저장·수집 실행·복원 성공이 아니다.
