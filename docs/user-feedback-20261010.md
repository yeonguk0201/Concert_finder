## 로컬 검증

- Node 26개 + UI 51개, 총 77개 회귀 검사 통과. 밴드 추가 SQL 검사 1개 별도 통과(합계 78개).
- lint·build 통과. 기존 500kB 초과 청크 경고 유지.
- 원격 공개 카탈로그를 읽는 로컬 앱에서 MCR 별칭 검색, 검색 결과·건수·설정 이동, 긴 제목과 6색 썸네일 확인. 데스크톱과 320/390px 모바일에서 가로 넘침 없음, 제목 경계 안에 표시됨 확인. 새 탭 콘솔 오류/경고 없음.
- 로그인 계정의 설정·기기 해제·관리자 이동은 자동 모의 검사로 확인했다. 실제 로그인 브라우저에서 기기 해제나 운영 데이터 변경은 수행하지 않았다.
- [React 점검](../src/App.tsx): 조건부 설정 마운트, 사용자 ID별 기기 패널 key·응답 격리 유지, 입력/버튼 이름·폼 submit 제공, 파생 목록은 state로 중복 저장하지 않음.

## 밴드 목록 확장

[밴드 등록 SQL](../supabase/manual/register-band-starter-catalog.sql)은 국내 DAY6·잔나비·실리카겔·혁오, 일본 ONE OK ROCK·RADWIMPS·King Gnu·SEKAI NO OWARI·요루시카·MY FIRST STORY, 해외 Muse·Radiohead·Coldplay·Foo Fighters·Arctic Monkeys·Linkin Park를 추가한다. 한글·일본어 별칭을 함께 등록한다.

밴드/공식 채널 자료 확인일은 2026-10-10이다. 참고: [DAY6 공식 프로필](https://day6.jype.com/profile), [잔나비 공식 링크](https://linktr.ee/bandjannabi), [실리카겔 공식 채널을 안내하는 KBS](https://world.kbs.co.kr/service/contents_view.htm?board_seq=447843&id=&lang=j&menu_cate=artist), [혁오 채널을 연결하는 아티스트 정보](https://www.melon.com/artist/detail.htm?artistId=785589). 나머지 공식 사이트는 SQL 각 행에 기록했다. 공연 발표를 확인한 목록이 아니다.

적용 방법: 기존 프로젝트의 Supabase SQL Editor에서 SQL을 실행한다. 서비스 키를 프런트엔드에 넣지 않는다. 동명/동일 국가·별칭이 기존에 있으면 건너뛰며 기존 ID·설명·찜을 덮어쓰지 않는다. 다시 실행해도 중복이 생기지 않음을 PostgreSQL에서 확인했다. 적용 후 검색·한글 별칭·찜/재접속 유지·다기기 반영을 확인한다. 현재 원격 적용·실제 찜 성공은 미검증이다.

## 실제 공연을 확보하기 위한 다음 작업

현재 ualive 목록의 예정 공연은 [MCR·케니 지](https://ualive.com/concerts)로 확인했다. 첫 출처만으로 세 장르를 충분히 제공할 수 없으므로 밴드 등록과 공연 출처 확장을 각각 진행한다. 자동 수집 후보는 검수 전까지 공개하지 않는다.

1. 운영 검수 화면에서 ‘테스트 공연’, ‘알람용’, ‘해제 테스트’, ‘오아시스 등록/등록2/오아시스’의 출처·내용을 확인한다. 사용자가 임시로 만든 행을 식별한 뒤 **공개 중단**으로 처리하고 실제 MCR 데이터는 별도로 유지한다. 제목만으로 자동 삭제하지 않는다. 현재 공개 중단도 실행하지 않았다.
2. ualive 수집 후보·최근 성공/실패와 기존 MCR의 검증된 정보·라인업을 대조한다. 테스트 중 추가한 라인업이 남았는지도 확인한다.
3. 국내 출처 후보는 잔나비 [공식 안내](https://linktr.ee/bandjannabi)의 서울 예매 상세, DAY6 공식 일정에서 시작한다. 일본 밴드는 공식 TOUR/LIVE와 한국 주최사 공지를 대조한다. 날짜·장소·예매·라인업을 확인하기 전에는 공연으로 등록하지 않는다.
4. 새 출처의 접근·수집 범위·중복 처리·검수 흐름을 구현/검증한다. 확보한 실제 공연 수와 미지원 출처를 기록하며 가상 일정으로 목표 수를 채우지 않는다.

후속 근거는 [사용자 테스트 기록](user-testing.md)과 [공식 수집 운영](official-collection.md)에 연결한다. F001/F006의 운영 데이터 문제는 아직 열려 있으며, 수정한 UI도 배포 후 사용자 재확인이 필요하다.
