# 10/12 자동 수집·조건부 공개 구현

W26/W27 로컬 구현. 원격 적용·배포·24시간 관측과 실제 무인 공개는 아직 미검증이다.

## 동작

- 다중 출처 수집기를 GitHub Actions 매시간 17분 실행 경로에 연결했다. 수집기 전체는 Node/jsdom·순차 외부 조회를 사용하므로 짧은 Edge Function에 그대로 이식하지 않았다. 기존 Supabase Cron은 SQL/HTTP 실행에 사용할 수 있지만 현재 수집기 실행 환경은 아니다. GitHub 스케줄은 지연·미실행 가능성이 있으며 60분 이내 실행을 보장하지 않는다. 운영에서 누락되면 별도 Node 실행 호스트를 연결해야 한다.
- 출처별 실행 시작·예정/실제 시각·종료·3회 이내 수집 재시도·부분 실패·제외·공개·검수 건수를 남긴다. DB 잠금과 15분 임대로 같은 출처 동시 실행을 막고, 만료된 실행을 회수한다. 오래된 작업자의 업로드는 거부한다. 출처 하나가 실패해도 나머지를 실행한다.
- 업로드는 같은 실행 ID로 최대 3회 재시도한다. 성공 응답 유실 시 같은 실행을 다시 보내도 이중 공개하지 않는다. 기존 수동 수집 기록은 `legacy`, 자동 실행 기록은 별도 state로 구별한다. 기존 ingest RPC가 생성하는 legacy 요약은 호환용으로 유지한다.
- 서버가 출처 경로·어댑터 버전·한국 공연 근거·필수 날짜·공식 발표 확인·신원/장르 승인·원문 확인·검수 사유·중복을 검사한다. 같은 원문 재수집은 기존 공연을 수정하지 않는다. 기존 공연 변경과 겹치는 날짜/라인업 또는 같은 정규화 제목은 검수로 보낸다. 같은 제목의 별도 회차도 자동 병합하지 않는다.
- 관리자 제외/검수 완료는 자동 공개 차단 상태를 남긴다. 재수집으로 후보가 pending으로 바뀌어도 차단을 유지한다. 원문 ID와 기존 공연이 연결된 경우 공개 중단·수정 내용을 자동 덮어쓰지 않는다.
- 정책은 자동 공개 OFF로 시작한다. 초기 채움은 무알림이다. 관리자가 초기 채움 종료를 지정한 뒤에도 종료일 당일과 그 이전 발표는 무알림으로 처리한다. 수집 시각을 발표일로 만들지 않는다. 중요한 변경·사진 변경으로 신규 알림을 만들지 않는다.

**현재 파서는 공식 발표일·검증 출처를 확정하지 못하고 일부는 한국 공연·형식 검수도 남긴다. 따라서 현 후보는 자동 공개되지 않는 것이 정상이다.** 자동 공개 조건을 만족하는 실제 어댑터/원문 사례 확보는 남아 있다. 테스트에서 쓰는 검증된 페이로드는 운영 자료가 아니다.

## 적용과 운영

1. 기존 마이그레이션 이후 `20261012134538_automated_catalog.sql` 적용. 이 단계는 운영 데이터나 자동 공개 설정을 바꾸지 않는다.
2. `catalog-ingestion` GitHub environment의 기존 서버 전용 SUPABASE_URL·SUPABASE_SERVICE_ROLE_KEY 확인. workflow는 기본 브랜치에 반영돼야 schedule이 시작된다. 이번 작업은 push·병합·배포하지 않는다.
3. `node scripts/collect-catalog.mjs --upload --output=collection-report.local`로 후보·실행 기록을 확인한다. 수집 전체 실패는 재시도하고 상세 일부 실패는 partial로 남겨 다음 주기에 재수집한다.
4. 공식 근거로 대상 장르를 검증한 신원만 관리자 RPC `admin_approve_artist(identity_key,evidence_url)`로 승인한다. 신원 등록만으로 장르 승인하지 않는다.
5. 실제 어댑터 검증 후 관리자 RPC `admin_collection_policy(source_name,true,true,false)`로 출처별 자동 공개를 켠다. 초기 채움 종료는 마지막 인자를 true로 지정한다. 중단은 수집 또는 공개 인자를 false로 지정한다. 차단 해제는 `admin_candidate_automation(candidate_id,false)`다.
6. `admin_collection_health()`로 출처별 마지막 성공·현재 실행·2시간 지연/연속 실패를 확인한다. `collection_decisions`에 실행·후보 revision·정책 버전·판단 근거·공연 ID가 남는다. 독립 호스트에서 `node scripts/catalog-health.mjs`를 실행하면 지연/연속 실패에 종료 코드 1을 반환한다. 별도 자동 감시/운영자 알림 전달은 아직 설정하지 않았다.
7. 최소 24시간 동안 실제 시작 간격·실패 복구·신규/검수·초기 채움 무알림·두 브라우저 반영을 기록한다. 코드와 cron 변경만으로 W26/W27 운영 완료 또는 W18 시작 조건을 충족하지 않는다.

## 검증

PGlite 실제 SQL 실행으로 권한 차단, 출처 임대·만료 회수, 재전송 멱등성, 신원/장르 승인 조건, 자동 공개 OFF, 초기 채움 무알림, 이후 신규 공개의 동의한 사용자 2기기 각 1건 큐 생성, 중복 검수, 기존 공연 보존, 관리자 제외 유지, 잘못된 날짜 격리와 중단된 출처의 지연 경고 제외를 확인했다. Node runner의 제한 재시도·잠금 시 건너뛰기·최종 실패 기록을 확인했다. 원격 advisors와 실제 운영 쿼리는 원격 적용 후 수행해야 한다.
