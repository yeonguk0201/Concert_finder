# DB 중심 아티스트 검색과 카탈로그 정리

2026-10-13 사용자 피드백. 목표는 모든 아티스트를 수집하는 것이 아니라 국내 록·해외 록·J-pop 주요 아티스트를 선별 등록해 일반 검색을 DB 중심으로 단순화하는 것이다.

## 현재 상태

- 실제 Supabase DB의 아티스트는 사전 등록 후 총 54팀이다. 20팀 manifest는 신규 12팀·기존 8팀으로 등록 완료했다.
- 강진·김수희·윤종신은 이번 20팀에 포함되지 않은 기존 DB 항목이며 `장르 미검수`다. 일반 목록 조회가 대상 범주 검수 상태를 필터링하지 않아 노출된다. 특정 항목을 임의로 삭제하지 않았다.
- 사이트 관리자 UI는 검색 별칭과 대표 이미지 URL·출처·저작자·이용 조건을 편집한다. 이름·국적·서비스 노출 제외·파일 업로드는 아직 지원하지 않는다. 소유자는 Supabase 대시보드에서도 편집할 수 있지만 공연·찜 관계가 있으므로 행 영구 삭제보다 복구 가능한 제외 상태가 적합하다.
- DB는 클라우드에 아티스트/별칭/외부 ID, 공연/출연/출처/예매 일정, 계정별 찜/저장과 수집·수정 기록을 보관한다. 지정 사진은 URL과 권리 메타데이터를 저장하며 원본 파일 업로드/보관 기능은 없다. 배포나 브라우저 종료로 DB가 초기화되지 않는다.

## 실행 순서와 완료 판단

10/13 로드맵 개편에 따라 **W28 DB 관리 → W29 대상 검수/주요 목록·W30 사진 → W31 DB 전용 검색 → 자동 수집 운영·실제 통합 검증** 순서로 진행한다. 기존 DB 기본 구조를 다시 만드는 것보다 데이터 품질과 편집·복구·재수집 정책을 먼저 완성한다. 각 단계 완료 전 다음 단계의 완료로 표시하지 않는다.

- W28: 관리자 편집과 승인/보류/제외·복구, 권한·변경 이력·기존 관계 보존 및 재수집 시 제외 유지.
- W29: 범주별 우선 목록을 먼저 확정하고 항목마다 신원·대상 여부·별칭·중복을 검수한다. 등록 수로 완료를 판단하지 않고 누락과 보류 이유를 기록한다.
- W30: 직접 파일 업로드/보관·교체를 추가하고 파일 형식/크기·저장소 접근·권리 메타데이터를 검증한다. 저장소 방식과 보관 정책은 구현 시 결정한다. 우선 목록 사진을 확보하고 미확보 사유를 기록하며 Ado도 점검 대상이다.
- W31: 일반 검색은 승인된 DB 항목만 제공하고 외부 검색은 관리 도구로 남긴다. 카드 표시에서 외부 신원/사진 API 의존을 제거하고 이미지 최적화·캐시·실패 대체를 검증한다.
- 새 아티스트 자동 발견은 유지하되 승인/제외 정책을 적용한다. 주요 목록 사전 등록이 자동 수집 확대를 대체하지 않는다.

DB 관리 폼·로그인 접근·저장 실패 안내·모바일 사용 가능 여부는 기능 범위다. 디자인·탐색/설정 재배치·사진 출처 정보의 시각적 정돈은 W32로 미룬다. 사진 이용 조건 준수는 유지한다. 일정·공개 조건은 [로드맵](development-roadmap.md), 작업 상태는 [백로그](development-backlog.md)를 따른다. 이 문서 수정은 DB 정리나 검색 변경을 실제 수행한 기록이 아니다.

## 다음 구현 범위

1. 관리자에 목록 검색·이름/국적·분류·별칭·노출 제외/복구를 제공한다. 제외 항목의 재수집 재노출도 막고 기존 관계를 보존한다.
2. 범주별 주요 아티스트 등록 목록을 확대하고 동명 신원·중복·별칭을 검수한다. 일반 검색의 외부 아티스트 패널을 제거하며 외부 검색/등록은 관리 도구로 남긴다. 이번 수정에서 공개 외부 검색은 아직 제거하지 않았다.
3. 이미지 없는 주요 아티스트에 이용 근거를 확인한 대표 이미지를 선등록한다. 일반 카드의 선택적 외부 API 조회를 줄이고 저장된 이미지 URL을 즉시 렌더링한다. 이미지 파일 전송 자체의 대기까지 0이 되는 것은 아니므로 고정 크기·최적화·캐시도 적용한다. Ado 사진은 미지정 상태다.
4. 사진 출처는 이용 조건에 맞게 표시한다. CC BY 사진은 저작자·원본/라이선스·변경 안내를 보존하고 카드 밖 상세/정보 패널 등으로 정돈한다. 직접 제작·개별 허락 사진은 해당 이용 조건에 맞춰 표시 정책을 구분한다.

## 이번 UI 수정·검증

- 찜한 밴드 화면은 전체 DB 목록 대신 계정의 찜한 ID만 표시한다. 빈 상태도 아티스트 검색을 안내한다.
- 상단 비로그인 버튼을 `로그인`, 로그인 상태를 `계정·설정`으로 표시한다. 로그인 버튼을 누르면 이메일 폼이 바로 열린다.
- 카탈로그의 첫 조회 이후 갱신에서는 별도 로딩 행을 추가하지 않는다. 연결/계정 상태 문구 영역은 두 줄 높이를 확보했다.
- 관련 App 테스트 15개, 전체 UI 테스트 75개, lint·build 통과. 기존 500kB 초과 번들 경고 유지. 실제 로그인 브라우저에서 현재 찜한 3팀만 표시, 새로고침 전/진행 중 제목 위치 동일(313.458px), 로딩 행 0개, 390px 가로 넘침 없음을 확인했다. 실제 계정의 찜 목록은 바꾸지 않았다.
- 로그인 폼 진입은 컴포넌트 테스트로 검증했다. 사용자의 현재 로그인 세션은 유지했다. DB 정리/공개 검색 제거/사진 대량 지정은 이번 UI 수정에 포함하지 않았다.
