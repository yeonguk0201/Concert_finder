## 실행 순서와 완료 판단

10/13 로드맵 개편에 따라 **W28 DB 관리 → W29 대상 검수/주요 목록·W30 사진 → W31 DB 전용 검색 → 자동 수집 운영·실제 통합 검증** 순서로 진행한다. 기존 DB 기본 구조를 다시 만드는 것보다 데이터 품질과 편집·복구·재수집 정책을 먼저 완성한다. 각 단계 완료 전 다음 단계의 완료로 표시하지 않는다.

- W28: 관리자 편집과 승인/보류/제외·복구, 권한·변경 이력·기존 관계 보존 및 재수집 시 제외 유지.
- W29: 범주별 우선 목록을 먼저 확정하고 항목마다 신원·대상 여부·별칭·중복을 검수한다. 등록 수로 완료를 판단하지 않고 누락과 보류 이유를 기록한다.
- W30: 10/14 로컬 구현은 관리자 검사를 거친 Edge Function·공개 PNG 전용 버킷·새 경로 교체를 사용한다. 원본 최대 2MiB를 브라우저에서 최대 1024px PNG로 변환하고 서버에서 디코딩·재인코딩한다. 직접 브라우저 쓰기는 차단한다. 권리 메타데이터·이력과 이전 파일을 보존하며 자동 정리 기간은 아직 없다. 우선 목록의 파일 미확보 이유를 기록했고 Ado는 개별 재보관/변환/표시 허락이 확인되지 않아 미지정이다. 원격 적용·실제 파일 저장/교체·사진 확보를 끝내야 완료한다. [구체적인 정책·검증](artist-photos-20261014.md).
- W31: 일반 검색은 승인된 DB 항목만 제공하고 외부 검색은 관리 도구로 남긴다. 카드 표시에서 외부 신원/사진 API 의존을 제거하고 이미지 최적화·캐시·실패 대체를 검증한다.
- 새 아티스트 자동 발견은 유지하되 승인/제외 정책을 적용한다. 주요 목록 사전 등록이 자동 수집 확대를 대체하지 않는다.

DB 관리 폼·로그인 접근·저장 실패 안내·모바일 사용 가능 여부는 기능 범위다. 디자인·탐색/설정 재배치·사진 출처 정보의 시각적 정돈은 W32로 미룬다. 사진 이용 조건 준수는 유지한다. 일정·공개 조건은 [로드맵](development-roadmap.md), 작업 상태는 [백로그](development-backlog.md)를 따른다. 이 문서 수정은 DB 정리나 검색 변경을 실제 수행한 기록이 아니다.

## 구현 범위와 후속 작업

1. W28에서 관리자 목록 검색·이름/국적·분류·별칭·노출 제외/복구를 구현하고 실제 DB에서 검증했다. 제외 항목의 재수집 재노출을 차단하고 기존 관계를 보존한다. 운영 프런트·함수 배포는 대기다.
2. 범주별 주요 아티스트 등록 목록을 확대하고 동명 신원·중복·별칭을 검수한다. 일반 검색의 외부 아티스트 패널을 제거하며 외부 검색/등록은 관리 도구로 남긴다. 이번 수정에서 공개 외부 검색은 아직 제거하지 않았다.
3. 이미지 없는 주요 아티스트에 이용 근거를 확인한 대표 이미지를 선등록한다. 일반 카드의 선택적 외부 API 조회를 줄이고 저장된 이미지 URL을 즉시 렌더링한다. 이미지 파일 전송 자체의 대기까지 0이 되는 것은 아니므로 고정 크기·최적화·캐시도 적용한다. Ado 사진은 미지정 상태다.
4. 사진 출처는 이용 조건에 맞게 표시한다. CC BY 사진은 저작자·원본/라이선스·변경 안내를 보존하고 카드 밖 상세/정보 패널 등으로 정돈한다. 직접 제작·개별 허락 사진은 해당 이용 조건에 맞춰 표시 정책을 구분한다.

## 신규 등록 우선순위와 아티스트 상세 페이지 계획 · 2026-10-13

기존 등록분은 유지하고 앞으로의 등록 스킬에 유명도 우선 선발을 적용한다. Last.fm 청취자 수를 확보한 넓은 후보 풀에서 J-pop과 록 밴드를 각각 정렬한다. 기본 비중은 50:50으로 시작하며 사용자 요청에 따라 조정한다. 지표 누락·동명 신원 미확인은 임의 0점이나 검색 점수로 대체하지 않는다. 후보 풀과 Last.fm 이용자에 따른 편향이 있으므로 전 세계/한국 인기순으로 표현하지 않는다. 공식 계정 링크 후보는 외부 ID에 연결해 확보하고 공식 사이트 등으로 검증한 뒤 사용한다. 등록 스킬의 결과 파일에 인기 지표·출처·확인일·링크 검증 상태를 남기며 DB 저장 필드는 별도 구현 전까지 추가된 것으로 보고하지 않는다.

**W33 아티스트 상세 페이지는 계획 상태이며 이번에는 UI·DB 스키마를 구현하지 않는다.** W28~W31의 데이터/노출 정책을 바탕으로 별도 구현한다. 기능 범위는 다음과 같다.

- 목록의 아티스트 카드에서 영구 내부 ID를 사용하는 상세 주소로 이동한다. 상단에 대표 이미지·이름/원어명·검증된 장르·짧은 소개·찜 버튼을 배치한다. 기존 계정 찜 상태를 공유한다.
- Spotify·YouTube·Instagram·X·공식 사이트 중 확인된 공식 링크만 표시한다. 팬/동명/자동 생성 채널을 공식으로 표시하지 않는다. 소개에 근거가 없으면 비워 두고 허구 정보를 채우지 않는다.
- 해당 아티스트의 출연 관계에 연결된 공개 예정 한국 공연을 날짜순 카드로 표시한다. 공연명·공연장·날짜·예매 상태와 기존 공연 상세 진입을 제공한다. 혼합 페스티벌 출연도 포함하되 다른 아티스트의 공연을 이름만으로 연결하지 않는다. 날짜 미정은 별도 표시하고 취소/중단/과거 공연은 예정 목록 정책에 맞게 제외·구분한다.
- 예정 공연이 없으면 “현재 확인된 예정 공연이 없습니다”로 안내한다. 가상 fixture의 샘플 고지는 유지하며 저장을 푸시 알림 예약으로 표현하지 않는다.
- 목록은 이미지와 이름 중심으로 간결하게 유지하고, 상세에는 공식 링크와 필요한 사진/정보 크레딧을 정돈한다. 출처를 상세에 모으는 방식은 해당 이미지 이용 조건이 허용할 때만 적용한다. 플랫폼 링크를 넣었다는 사실이 사진 사용 조건 충족을 대신하지 않는다.
- 이미지는 무표기 사용 허락이 확인된 공식 홍보 사진·CC0/퍼블릭 도메인을 우선 검토한다. 그 외 사진의 저작자·출처·라이선스·플랫폼 표시 조건을 보관하고 준수한다. 사진 미확보/실패는 이니셜로 대체한다. YouTube/Spotify API 이미지 도입은 별도 사용 조건·공식 신원·갱신 검토 후 결정한다.

완료 기준은 직접 주소 진입/새로고침/뒤로가기, 비공개·보류·제외·없는 ID의 비노출, 찜 상태/계정 전환, 출연 관계별 공연 카드·빈 상태·로딩/오류 복구, 모바일/키보드 접근, 소스별 이미지 표시 조건 검증이다. 프로필·공식 링크·인기 지표의 저장 스키마와 관리자 수정/검증 이력은 구현 시 설계하며 현재 등록 RPC의 description을 임시 저장소로 사용하지 않는다.

## 이번 UI 수정·검증

- 찜한 밴드 화면은 전체 DB 목록 대신 계정의 찜한 ID만 표시한다. 빈 상태도 아티스트 검색을 안내한다.
- 상단 비로그인 버튼을 `로그인`, 로그인 상태를 `계정·설정`으로 표시한다. 로그인 버튼을 누르면 이메일 폼이 바로 열린다.
- 카탈로그의 첫 조회 이후 갱신에서는 별도 로딩 행을 추가하지 않는다. 연결/계정 상태 문구 영역은 두 줄 높이를 확보했다.
- 관련 App 테스트 15개, 전체 UI 테스트 75개, lint·build 통과. 기존 500kB 초과 번들 경고 유지. 실제 로그인 브라우저에서 현재 찜한 3팀만 표시, 새로고침 전/진행 중 제목 위치 동일(313.458px), 로딩 행 0개, 390px 가로 넘침 없음을 확인했다. 실제 계정의 찜 목록은 바꾸지 않았다.
- 로그인 폼 진입은 컴포넌트 테스트로 검증했다. 사용자의 현재 로그인 세션은 유지했다. DB 정리/공개 검색 제거/사진 대량 지정은 이번 UI 수정에 포함하지 않았다.
