# W31 승인된 DB 전용 아티스트 검색

2026-10-20 KST. 작업 브랜치 `codex/feat-db-artist-search`, 기준 `origin/dev`의 `014ae2b`.
예약 검수의 원래 체크아웃과 분리된 관리형 worktree에서 구현했다.

## 변경한 동작

- 일반 검색·찜 목록은 승인된 DB 항목만 사용한다. 이름과 각 별칭을 NFKC/소문자로 정규화해 한국어·영문·일본어·전각 검색을 지원하며 동명이인은 ID로 구분한다. 공연 없는 아티스트도 기존 계정 찜 API를 사용한다.
- 공개 외부 검색·즉시 등록/찜 컴포넌트를 제거했다. 관리자는 검색 화면의 이동 버튼과 기존 관리자 `ArtistLookup`으로 외부 검색/가져오기를 사용한다. 가져온 항목은 별도 검수 후 승인한다.
- `artist-search`의 검색과 가져오기 모두 사용자 검증과 `is_catalog_admin` 확인을 거친다. 미인증 401, 일반 계정 403을 캐시·외부 요청·쓰기 전에 반환한다. 관리자 import는 기존 신원 충돌/보류·제외 검사를 유지한다.
- 공개 `bands_read` RLS와 공개 공식 프로필 RPC를 승인 전용으로 변경하고 새 찜도 승인 항목만 허용한다. 기존 관리자 정책/RPC는 미검수·보류·제외를 계속 조회한다. 기존 찜과 공연 관계를 삭제하지 않으며 비공개 찜은 보존 건수를 안내하고 승인 후 다시 표시한다.
- 카탈로그는 승인 항목을 500개씩 이름/ID 순서로 조회한다. 공식 링크·사진 메타데이터는 DB에서 병렬 조회하지만 이름·찜 버튼 표시를 지연하지 않는다. 이전 조회 응답이 새 승인 상태를 덮어쓰지 않게 effect 정리를 유지한다.
- 카드의 외부 `artist-photo` 호출과 외부 ID 조회 대기를 제거했다. 저장된 대표 사진/유효한 채널 사진만 사용한다. 수동/숨김 모드, lazy loading, 고정 80px 크기, 출처 표기·캐시 만료·이미지 실패 이니셜을 유지한다. 두 사진 출처가 모두 실패해도 실패 이미지가 재등장하지 않는다. 기존 서버 사진 API 자체는 유지한다.
- 승인되지 않은 출연진의 국적을 알 수 없을 때 공개 공연을 국내로 추정하지 않고 `분류 미정`으로 표시한다. 페스티벌과 확인 가능한 국내/내한 분류는 유지한다. 기존 공연/샘플 안내를 보존한다.

## 적용 순서와 남은 조건

1. 검수된 우선 아티스트의 실제 승인 상태·사진 상태와 누락을 확인한다. 검수 보고서의 유지 결과만으로 일괄 승인하지 않는다. 예약 검수와 승인 적용의 권한/완료 여부를 별도로 확인한다.
2. 승인 목록이 준비되면 `20261019170609_approved_artist_catalog.sql`, `artist-search` 함수, 프런트를 하나의 출시 범위로 반영한다. 먼저 관리자 전용 함수를 배포하면 이전 공개 외부 패널은 401/403을 받으므로 공개 검색 제거 프런트와 함께 조정한다.
3. 운영에서 비로그인/일반/관리자 권한, 실제 이름·별칭·동명이인·없는 이름, 공연 없는 찜·새로고침·계정 전환, 사진 실패·캐시 만료를 확인한다. 기존 알림/공연/저장 관계와 예약 검수 동작도 회귀 확인한다.
4. 그 뒤 W21/W26/W27 수집 운영·24시간 관측과 실제 통합 검증을 이어간다.

이번 작업에서 운영 DB 쓰기·상태 승인·원격 SQL 적용·함수 배포·푸시·PR·병합·프런트 배포는 수행하지 않았다. W31은 로컬 구현/검증 진행이며 운영 완료로 표시하지 않는다.
