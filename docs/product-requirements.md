# encore. 베타 출시 요구사항

기준일: 2026-10-10 · 조건부 목표: 2026-10-19 베타 공개 / 2026-10-26 1차 완성

10/6 초기 요구사항을 10/10 사용자 결정으로 개편했다. 다중 출처·매시간 수집·조건부 자동 공개와 실제 공연 확보를 외부 사용자 테스트보다 우선한다. 아래는 구현 기준이며 현재 완료 여부는 로드맵·작업 목록의 실제 기록을 따른다. 새 정책이 이미 구현됐다는 뜻이 아니다.

관련 문서: [개발 일정](development-roadmap.md) · [작업 목록](development-backlog.md)

## 1. 목표 사용자와 핵심 흐름

국내 록·해외 록·J-pop의 밴드와 록 성향 아티스트를 좋아하며, 한국 어느 지역에서든 이들의 공연을 알고 싶은 사람을 대상으로 한다. 콘서트·록 페스티벌 및 혼합 페스티벌의 대상 아티스트 출연을 포함한다. 국적만으로 장르를 판정하지 않고 공식 소개 등 분류 근거를 관리한다. 일반 팝·재즈·클래식·아이돌 전체를 다루는 종합 공연 서비스로 확대하지 않는다. 상세 범위는 [자동 수집·공개 계획](automated-catalog-plan.md)을 따른다.

핵심 흐름은 다음과 같다.

1. 사용자가 홈에서 대상 장르의 최근 국내 공연·내한 발표를 발견한다.
2. 계정에 로그인하고 좋아하는 밴드를 찜한다.
3. 수집기가 여러 공식 출처를 매시간 확인하고, 출처·대상 아티스트·필수 정보·중복/충돌 검사를 통과한 신규 공연은 자동 공개한다. 불확실한 후보와 중요한 변경은 관리자 검수로 보낸다. 공개된 DB 변경은 열린 앱에 새로고침 없이 반영된다.
4. 해당 밴드를 찜하고 알림에 동의한 사용자가 신규 소식을 받는다.
5. 사용자가 공연을 저장하고, 공개된 예매 시간과 공식 예매처를 확인한다.
6. 동의한 사용자에게 예매 시작 1시간 전 알림을 전달한다.

외부 사용자 테스트와 베타의 선행 조건은 세 범주의 수집 경로·독립 운영 주체 최소 2곳, 기본 60분 이하 주기, 조건부 자동 공개, 실제 한국 공연과 DB 변경의 화면 반영이다. 운영 24시간 반복 실행과 데이터 준비 기준을 검증한 뒤 외부 테스트를 시작한다. 관리자 직접 등록은 검수·오류 수정·누락 보완을 위한 경로다. 수동 입력만으로 자동 수집 완료를 표시하지 않는다. 빠른 알림은 최초 공식 발표와 내부 공개 시각을 비교해 측정하며, 데이터 확보 전에는 실시간·최속을 약속하지 않는다.

## 2. 계정과 권한

| 역할 | 허용 동작 |
| --- | --- |
| 비로그인 방문자 | 공개된 공연·밴드 탐색, 상세·공식 출처·예매 링크 확인 |
| 로그인 사용자 | 본인의 찜·저장 일정·알림 설정·기기 등록 관리 |
| 관리자 | 밴드·공연·라인업·출처 등록 및 수정, 검수, 공개·공개 중단, 취소 처리 |

초기 로그인 방식은 이메일 로그인 링크로 한다. 이메일 소유 확인 후 세션을 발급한다. 만료·이미 사용한 링크·다른 기기에서 링크를 여는 경우·로그아웃을 검증한다. 비밀번호와 소셜 로그인은 첫 베타에서 제외한다.

화면에서 관리자 메뉴를 숨기는 것만으로 권한을 구현하지 않는다. 데이터 접근 단계에서도 사용자별 데이터와 관리자 변경 권한을 검증한다. 사용자가 자기 계정 설정으로 관리자 권한을 얻을 수 없어야 한다.

베타에는 계정 삭제 경로와 본인 데이터 삭제 흐름을 제공한다. 삭제 후 알림 기기·예약·찜·저장 일정은 활성 상태로 남지 않아야 한다. 개인정보 처리 안내는 실제 저장 데이터와 운영 방식이 확정된 뒤 작성한다.

## 3. 화면별 동작과 완료 기준

### 홈

- 내 밴드 소식: 찜한 밴드가 출연하는 공개 공연과 앞으로 열릴 예매 일정을 보여준다. 비로그인/찜 없음에는 로그인·밴드 찜 안내를 표시한다.
- 최근 공연 발표: 찜 여부와 관계없이 대상 국내 록·해외 록·J-pop 아티스트의 한국 콘서트·페스티벌 출연을 표시한다. 국내/내한을 구분하며, 기존 최근 내한 전용 홈의 국내 공연 노출 보완도 W21/W11 후속 범위에 포함한다.
- 예매 임박: 앞으로 열리는 예매를 시간순으로 표시한다. 예매 미정과 종료된 예매는 구분한다.
- 이미 종료된 공연은 기본 홈의 예정 공연 목록에서 제외한다. 취소 공연은 상태를 명시하고 추천 목록에서는 제외한다.
- 공식 발표 시각과 앱 공개 시각을 별도로 관리한다. 발표 시각은 확인된 정밀도로 표시하며, 날짜만 확인했으면 임의 시간을 만들지 않는다.

완료 기준: 비로그인·찜 없음·공연 없음 상태가 각각 동작하고, 내 밴드 결과와 모든 내한 결과를 구분하며, 정렬 기준을 화면에서 확인할 수 있다.

### 밴드 탐색과 찜

- 국내 록·해외 록·J-pop 대상 아티스트를 탐색하고, 공연 유무와 관계없이 공식 이름과 등록된 한글·영문·일본어 별칭으로 검색·찜한다.
- 같은 이름의 다른 밴드는 고유 ID로 구분하고 국적·설명으로 식별한다.
- 수집에서 처음 발견한 대상 아티스트는 공식 식별자·이름·장르 근거가 확정되면 별칭과 함께 자동 등록한다. 사전 수동 등록에 의존하지 않으며 동명이인·불확실 분류는 검수로 보낸다. 출처 식별자와 기존 ID 연결을 보존한다.
- 로그인 사용자의 찜은 계정별로 저장하고 새로고침·다른 기기에서 유지한다.
- 실제 계정에는 샘플 밴드를 자동으로 찜하지 않는다. 초안의 기본 찜은 데모에서만 유지한다.
- 비로그인 상태의 찜·일정 저장 버튼은 로그인으로 안내하고 완료 후 원래 공연/밴드로 돌아온다.
- 기존 데모의 로컬 저장 항목은 실제 계정으로 자동 이전하지 않는다. 가상 공연 ID가 실제 공연 저장에 섞이지 않아야 한다.

완료 기준: 찜/해제의 서버 실패를 안내하고, 실패한 저장을 성공으로 표시하지 않는다. 사용자 A의 데이터가 사용자 B에게 보이지 않는다.

### 공연 탐색

- 검색 대상: 공연명, 출연 밴드 공식 이름·별칭, 공연장.
- 필터: 전체/내한/국내/페스티벌, 전국/지역. 해외 공연은 수집 범위에서 제외한다.
- 페스티벌 여부와 내한 여부는 독립적으로 판정한다. 해외 밴드가 포함된 국내 페스티벌은 내한 필터와 페스티벌 필터 모두에서 찾을 수 있다.
- 내한 필터는 공개된 라인업에 해외 밴드가 포함된 한국 공연을 뜻한다. 국내 필터는 국내 밴드가 포함된 한국 공연을 뜻한다. 혼합 라인업은 두 필터에 모두 나타날 수 있다.
- 정렬: 최근 발표순(공식 발표 기준) / 공연일 가까운 순. 발표일 미확인 항목은 최근 발표 정렬의 뒤에 두고 미확인으로 표시한다.
- 밴드가 페스티벌 제목에 없어도 라인업으로 검색된다. 출연일이 확인되면 페스티벌 전체 기간과 함께 표시한다.

완료 기준: 국내·해외 혼합 페스티벌, 동명이인 밴드, 여러 지역·검색 복합 조건, 빈 결과, 로딩·오류를 검증한다.

### 공연 상세와 저장 일정

- 공연명, 공연 기간·시간, 지역·공연장, 출연 밴드, 가격, 예매 시각, 공식 출처와 예매 링크를 표시한다.
- 미발표 시간·장소·가격·예매처는 미정으로 표시한다. 0원이나 임의 날짜로 대체하지 않는다.
- 페스티벌은 시작·종료 기간을, 여러 회차의 단독 공연은 회차를 구분한다.
- 베타 알림은 공연별 일반 예매 1개 일정에 한정한다. 선예매·여러 단계 판매의 알림은 후속으로 두고 필요하면 상세 설명과 출처로 안내한다.
- 저장 일정은 티켓 오픈순으로 정렬하고 미정 항목은 별도로 표시한다. 캘린더 파일도 실제 정보를 기준으로 생성한다.
- 일정 저장과 알림 동의는 별개다. 저장됐더라도 동의하지 않았으면 알림이 예약됐다고 표시하지 않는다.
- 종료된 공연과 취소된 공연도 사용자가 저장한 목록에서는 상태를 명시해 확인할 수 있다. 취소·지난 예매에는 리마인더를 보내지 않는다.

완료 기준: 미정·시간 변경·취소·종료된 항목, 저장 실패·해제, 캘린더 시간 변환을 확인한다.

### 관리자 등록과 공개

- 상태: 초안 → 검수 대기 → 공개. 공개 중단은 별도 처리한다. 취소는 공연의 실제 상태로 기록한다.
- 실제 공연 공개 조건: 밴드 ID, 한국 공연 여부, 공식 출처 URL, 확인된 공연 날짜 또는 기간, 공식 발표 확인 결과를 갖춘다.
- 날짜가 미정인 발표는 베타 공연으로 공개하지 않고 검수 대기에 둔다. 장소·예매 시각·가격은 미정으로 등록할 수 있다.
- 후보와 공개 데이터를 구분한다. 검증된 자동 공개 정책 또는 관리자 공개를 통과한 정보만 일반 사용자에게 노출한다. 출처 URL이 있다는 이유만으로 자동 공개하지 않는다. 공개 판단·정책 버전·원문·실행 ID를 남긴다.
- 관리자 수정/공개 중단/예외 지정을 재수집으로 덮어쓰거나 자동 재공개하지 않는다. 출처별 자동 공개 중지와 재검수 경로를 제공한다.
- 공개된 항목을 수정하면 변경 이력과 수정 시각을 남긴다. 최초 공개 시각은 수정할 때 갱신하지 않는다.
- 공식 출처 예: 밴드 공식 채널, 주최사 공식 발표, 공식 페스티벌 발표, 공식 예매처. 실제 수집 가능 여부는 별도로 확인한다.
- 중복 후보는 출처 링크·밴드·기간·공연장으로 비교하되, 별개 회차를 잘못 병합하지 않도록 관리자 판단을 거친다.

완료 기준: 일반 계정의 변경이 차단되고, 검수 전 항목이 검색이나 알림 대상에 포함되지 않는다. 수정·재공개로 신규 알림이 반복되지 않는다.

### 자동 수집과 DB 변경의 화면 반영

- 세 범주의 공식 API/페이지 수집 경로와 독립 운영 주체의 출처 최소 2곳을 검증한다. 출처/경로/어댑터별 신뢰·장르·공개 정책을 등록한다.
- 기본 수집 간격은 매시간 1회, 60분 이하다. 접근 정책·요청 제한을 지키며 실패 재시도·동시 실행 잠금·예정/실제 시작·마지막 성공을 기록한다. 두 주기 연속 성공이 없으면 운영 오류로 알린다. 주기를 허용하지 않는 출처는 예외를 안내하고 대안 경로를 확보한다.
- 출처별 원본 식별자·URL·가져온 시각·마지막 성공·실패 및 변경 내역을 남긴다. 같은 결과의 재수집은 공연이나 공개 변경을 중복 생성하지 않는다. 다른 회차·동명이인 밴드를 잘못 합치지 않는다.
- 검증된 공식 출처·한국 공연·대상 아티스트 고유 ID·공연명/날짜·원문/발표 근거·중복/충돌 검사를 모두 통과한 신규 공연을 자동 공개한다. 장소/가격/예매 미정은 임의 값으로 채우지 않는다.
- 미확인·출처 충돌·파싱 실패와 기존 공연의 날짜/예매/라인업/취소 등 중요한 변경은 검수 후보로 남긴다. 누락된 조회 결과만으로 공연을 취소하지 않는다. 연기·취소는 명시적인 공식 근거로 처리한다. 검수 전 후보는 일반 사용자 화면과 알림에서 제외한다.
- 공개 데이터 및 본인 찜·저장 변경을 구독하고 관련 조회를 갱신한다. 계정 전환·로그아웃 시 이전 계정 구독과 데이터를 제거한다. 이벤트 내용만을 신뢰하지 않고 RLS가 적용되는 재조회로 상태를 확인한다.
- 연결 복구·탭 재활성화 시 최신 상태를 재조회한다. 구독 실패는 갱신 상태와 다시 불러오기 경로를 제공하며 기존 필터·검색·상세 위치를 유지한다.
- 외부 발표→수집→검수→DB 공개→화면 반영의 시각을 구분한다. 수집 주기와 화면 반영 지연을 각각 측정하고 지원 범위를 안내한다. 화면 구독은 앱이 닫혀 있을 때의 푸시 발송과 별개다.

완료 기준: 세 범주의 실제 수집 경로·다중 출처·운영 24시간 매시간 실행·자동 공개/예외 검수·중복 방지를 확인하고 자동 공개한 신규 공연이 두 브라우저에 새로고침 없이 반영된다. 초기 채움 무알림·관리자 예외·정책 중단을 검증한다. 연결 중단·복구·계정 전환에서 최신 상태와 접근 격리가 유지된다. 수집 코드만 작성하거나 SQL로 입력한 데이터만으로 이 흐름의 완료를 선언하지 않는다.

## 4. 알림 규칙

### 신규 발표 및 라인업 추가

- 실제 데이터 운영을 시작한 이후 최초 공개한 공연을 대상으로 한다. 초기 데이터 채우기에는 알림을 보내지 않는다.
- 공개 당시 찜한 밴드가 출연하고 신규 소식 알림에 동의한 사용자를 대상으로 한다.
- 공개된 페스티벌에 새로운 찜 밴드가 추가되면 신규 라인업 소식으로 전달한다. 밴드 표기 수정은 라인업 추가가 아니다.
- 찜을 나중에 추가했을 때 지난 신규 발표 알림을 다시 보내지 않는다. 해당 공연은 홈·검색에서 확인한다.
- 한 공연에 찜한 밴드가 여러 팀 있어도 같은 공개 변경에 대해 사용자에게 한 번만 전달한다.
- 공연 ID와 공개 변경 ID 및 사용자 ID를 기준으로 발송 중복을 막는다. 여러 기기에 전달될 수 있으나 같은 기기에 동일 변경을 반복 발송하지 않는다.

### 예매 1시간 전

- 저장 일정, 예매 전 알림 동의, 유효한 전달 경로, 미래의 예매 시각이 모두 있어야 예약한다.
- 예매 1시간 이내에 저장한 경우 예매 시작 전이면 즉시 한 번 안내한다. 이미 시작된 예매는 알림 없이 현재 상태만 보여준다.
- 예매 시각 변경 시 기존 예약을 무효화하고 새 시각 기준으로 갱신한다. 변경 이후 1시간 이내라면 위의 즉시 안내 규칙을 적용한다.
- 저장 해제·알림 해제·계정 삭제·공연 취소·공개 중단 시 남은 예약을 취소한다. 실제 발송 직전에도 현재 조건을 다시 확인한다.
- 알림을 눌렀을 때 해당 공연 상세로 이동한다. 삭제·공개 중단한 공연이면 상태 안내를 보여준다.

### 전달과 검증

웹 푸시가 우선 후보이며 10/7 실제 휴대폰 실험 후 확정한다. 이메일은 대안이다. 선택되지 않은 전달 경로와 지원하지 않는 기기를 지원한다고 표시하지 않는다. 계정 로그인 이메일과 공연 알림 수신 동의는 구분한다.

발송 요청 성공과 사용자 기기 수신은 구분한다. 기록에는 예약·발송 시도·성공/실패·무효화와 이유를 남긴다. 서버가 보장할 수 없는 읽음/수신 상태를 추정하지 않는다. 오류 재시도는 횟수와 기간을 제한하고 예매 시작이 지난 리마인더는 폐기한다.

관리자 최초 공개 및 예매 예약의 내부 처리 목표는 정상 운영에서 5분 이내이며 구현 후 측정한다. 실제 단말 수신은 전달 서비스·네트워크 영향이 있어 보장하지 않는다. 측정 전에는 제품의 속도 약속으로 사용하지 않는다.

## 5. 날짜·데이터와 초기 범위

- 저장 시각은 시간대 정보를 포함하고 사용자 화면과 예약은 한국 시간 기준으로 표시한다.
- 발표 날짜만 확인된 항목과 정확한 시각이 확인된 항목을 구분한다. 미래의 공연 날짜만 확인했다고 발표 시각을 만들지 않는다.
- 밴드, 공연, 출연 관계, 예매 일정, 출처, 사용자 찜·저장, 발송 기록은 독립적인 개념으로 관리한다. 실제 테이블 설계는 다음 작업에서 확정한다.
- 초기 조사 대상은 국내·해외 밴드 20~30팀이다. 공연 수를 맞추기 위해 가상 공연을 실제 데이터로 공개하지 않는다.
- 게시된 공식 정보를 출처와 함께 자동 수집하고 검수한다. 직접 등록은 누락을 보완한다. 10/11 W21에서 공식 공연 포스터·공연 전용 대표 이미지 수집과 표시를 구현한다. 출처별 이용·외부 링크 조건과 공연 매칭을 확인하고 원문·이미지 출처를 보존한다. 원본 비율과 전체 내용을 유지하며, 이미지가 없거나 로딩에 실패하면 자체 제작 타이포 썸네일로 대체한다. 임의 포스터·사진 사용은 제외한다. 이미지 확보 실패만으로 정상 공연 공개를 막거나 이미지 변경만으로 신규 알림을 만들지 않는다. [상세 기준](automated-catalog-plan.md)을 따른다.
- 실제 운영 데이터와 데모 데이터를 분리하고 일반 사용자 화면에서 섞어 표시하지 않는다.
