# 계정 삭제와 운영·개인정보 안내

W19 구현일: 2026-10-09. 앱 하단에서 지원 환경·알림 중단·수집 정보·삭제 범위를 로그인 없이 읽을 수 있다. 운영자/문의 창구와 제공자별 처리 지역·보관/백업 정책은 공개 전에 확정해야 한다. 이 문서는 법적 검토 완료를 의미하지 않는다.

## 계정 삭제 적용

새 DB 마이그레이션은 없다. 기존 FK cascade를 전체 마이그레이션 적용 PostgreSQL 테스트에서 확인했다. 서버 전용 Edge Function `delete-account`를 추가했다.

```sh
npx --yes supabase@2.120.0 functions deploy delete-account --project-ref <프로젝트-ref> --use-api
```

현재 프로젝트에 로그인·연결된 Supabase CLI로 배포한다. `SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`는 호스팅 Edge 런타임의 서버 환경변수를 사용한다. 서비스 키를 VITE 변수나 브라우저에 넣지 않는다. [공식 Admin 삭제 API](https://supabase.com/docs/reference/javascript/auth-admin-deleteuser)를 사용한다. config의 `verify_jwt=false`는 인증 생략을 뜻하지 않는다. 함수가 bearer를 Auth `getUser`로 서버 검증하고, 검증한 사용자 ID만 삭제에 사용한다. 요청의 expectedUserId는 계정 전환 감지용 비교값이며 삭제 권한의 근거가 아니다. 요청 body/토큰을 로그에 남기지 않는다.

함수 배포와 프런트 배포는 별도다. 배포되지 않은 함수 호출은 삭제 성공으로 표시하지 않는다. CORS는 브라우저 요청을 허용하지만 인증/확인 문구 없는 삭제는 차단한다. 프런트는 계정 전환 시 확인 입력을 초기화한다.

## 삭제 데이터와 제한

| 데이터 | 삭제 시 처리 |
| --- | --- |
| Auth 사용자·연결 인증 정보 | Auth Admin API의 hard delete |
| 찜·저장 일정·알림 동의·계정 신호 | auth.users FK cascade |
| private 기기·구독 키·발송 기록·시도 기록 | cascade, 후속 워커 대상에서 제외 |
| 관리자 권한 | cascade |
| 공연 검수·공개 이력 | actor_id는 NULL로 처리, 공연 정보 유지 |
| 다른 계정과 공개 카탈로그 | 유지 |
| 기기에 이미 전달한 알림·캘린더 파일 | 회수 불가, 사용자 직접 삭제 |
| 다른 기기의 화면 캐시 | 즉시 지워진다고 보장하지 않음; 갱신·재로그인으로 확인 |
| 제공자 운영 로그·백업 | 제공자 정책 확인 필요; 즉시 삭제 약속 금지 |

삭제와 동시에 이미 승인되어 외부 제공자로 전송 중인 요청까지 취소하는 것은 보장하지 않는다. 계정 삭제는 브라우저 자체의 푸시 권한 철회와 다르다. 사용자가 브라우저/OS 설정에서도 해제할 수 있다.

[Supabase 사용자 관리 안내](https://supabase.com/docs/guides/auth/managing-user-data)에 따라 삭제 뒤에도 발급된 JWT는 만료 전 남을 수 있다. 이 앱의 개인 저장은 소유자 RLS와 auth.users FK로 재생성을 막고, 관리자 권한은 사용자 행 삭제 시 함께 제거된다. 공개 카탈로그는 비로그인에게도 공개되어 있다. 다른 기기의 즉각적인 로그아웃 화면 전파는 별도 실기기 검증 항목이다.

원격 삭제 검증은 [기기 통합 검증 O03/O04](device-integration-validation.md)를 따른다. 삭제용 계정에서 실제 Auth 제거·다른 기기 쓰기 실패·발송 중단·재가입 빈 목록을 확인해야 W19 삭제 검증을 완료로 바꾼다.

## 운영 확인과 장애 대응

- 수집: [공식 수집 운영](official-collection.md)의 마지막 성공 시각·실패·검수 대기를 확인한다. 후보를 검수하지 않고 자동 공개하지 않는다.
- 알림: [Cron 점검](supabase-notifications.md)과 `verify-notification-cron.sql`로 반복 실행·HTTP 결과를 확인한다. 제공자 수락과 실제 수신을 나눠 기록한다.
- 저장/연결 오류: 화면의 재조회·재시도를 확인하고 계정별 RLS를 유지한다. 장애 해결을 위해 서비스 키를 브라우저에 넣거나 권한을 넓히지 않는다.
- 삭제 오류: 실패 요청은 401/409/503 등 결과만 조사한다. 응답 유실 후 실제 삭제가 끝났을 가능성이 있으므로 먼저 Auth 사용자 존재와 관련 행을 확인한다. 서버에 계정이 없으면 재가입은 새 ID·빈 저장으로 시작한다.
- 복구: 삭제 기능 장애 시 해당 기능을 이전 커밋으로 되돌리거나 함수 배포를 되돌리고 안내한다. 사용자 삭제로 제거된 데이터는 앱에서 복원할 수 없다. 테스트 편의를 위해 복구를 약속하지 않는다.
- 문의 수집: KST 시각·배포 커밋·기기 버전·재현 단계·안전한 오류 코드만 수집한다. 토큰·인증번호·구독 키·이메일 본문을 요구하지 않는다.

## 공개 전 확정 항목

- 운영자 표시명과 실제 문의 수신 창구.
- Supabase/Vercel/설정된 SMTP/푸시/Google Fonts 제공자별 처리 지역·목적·위탁/이전 안내와 보관·백업 정책. 현재 CSS는 Google Fonts를 요청한다.
- 실제 기기 버전별 지원 범위, 접근성 스크린리더 점검 결과.
- 원격 삭제 검증 결과, 삭제 후 알림/다기기 접근 차단 결과.

미확정 항목을 임의로 채우거나 개인정보 안내가 모두 완료됐다고 표시하지 않는다.

### 배포 후 사용자 확인 · 2026-10-10

사용자가 실제 계정 삭제가 동작한다고 확인했다. 위 배포 시점의 미실행 기록 이후 실제 삭제 흐름 성공을 확인한 것이다. 사용자는 이어서 삭제 후 알림 미수신과 같은 이메일 재가입 시 빈 목록을 확인했다. 미수신 관측 시간·서버 발송 기록은 미제공이다. 서버 Auth/개인 데이터 행 제거의 직접 조회, 삭제 후 타 기기 접근 차단·타 계정 유지는 아직 별도 확인이 필요하다. O03 전체와 O04를 완료로 확대 표시하지 않는다.
