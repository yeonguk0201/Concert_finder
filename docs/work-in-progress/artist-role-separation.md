# 작업 중: 아티스트 역할과 ID 규칙 분리

후속: [등록 차단과 출처 범위 수정·격리 검증](registration-source-scope.md). 아래는 역할 분리 단계의 기록이며 실제 등록/공개 ON 성공을 뜻하지 않는다.

다음 구현: [공개 실행기 보완과 로컬 무알림 검증](publication-executor.md). 운영 적용·실제 후보 최종 readback·공개 ON은 별도 단계로 남아 있다.

2026-10-30 KST 사용자 요청. 실제 등록 전에 이 단계의 구현·검증을 먼저 마친다.

## 왜 하는가

외부 MusicBrainz 신원을 임의로 만드는 행위와 새 DB 행에 내부 UUID를 할당하는 정상 절차가 같은 금지로 해석됐다. 또한 아티스트 쓰기 예약과 공연 운영 읽기 전용 예약의 긴 지시문이 같은 채팅 이력에 섞여 역할이 충돌했다. 서버 인증/새 스키마로 우회하지 않고 현재 클라이언트·실행 지시의 경계를 분명히 한다.

## 이번 작업

1. 내부 bandId는 시스템의 새 행 번호, musicBrainzId는 실제 검증한 외부 신원이라는 계약을 명시한다. 같은 고정40팀/5시간 임대·불변journal·중복/버전/수동보호·receipt/검색readback을 유지한다. 기존pendingID는 재사용 대상으로 보존하고 새운영ID/등록은 이번에 실행하지 않는다.
2. queue CLI의 아티스트 역할을 명시적으로 선택하도록 하고, monitor/미지정 역할은 아티스트 변경 명령을 네트워크·파일쓰기 전에 거절하도록 한다. 역할 표시가 인증/승인을 대신하지는 않는다.
3. 실제 아티스트·감시 예약의 지시문을 각각의 역할 계약과 맞춘다. 다른 수집 예약·기존 워커·중지된 이전 예약·일정은 보존한다. 현재 사용자 요청은 구현/격리검증 단계이며 등록/승인/공개ON을 실행하지 않는다.
4. 잘못된 역할 거절/아티스트 정상경로/내부·외부ID 불변성/예약지시 일치를 격리검증한다. 실제queue SHA와 기존pending입력/상태가 그대로인지 확인한다. 필요한 lint/build 후 로컬커밋한다.

## 다음 작업(이번에 실행하지 않음)

- 이 단계 완료 후 등록 차단과 출처 범위를 해결한다. 기본 방향은 허용된 API의 공연 사실정보와 출처 링크이며 외부 본문·이미지는 수집/전재/다운로드 대상에서 제외한다. 기존 보존 자료는 삭제/덮어쓰기하지 않는다.
- 자료를 가져온 출처와 예매 링크 목적지를 구분하는 NOL 차단 보완은 사용자가 이후에 하기로 했다. 이번에는 해당 로직/테스트 기대값을 바꾸지 않는다.
- 실제 등록·승인/공연연결·공개실행기/무알림 최종검증·ON·발송·DDL·배포/push/PR/merge는 이번 단계에 포함하지 않는다.

## 완료 기준과 제한

- 로컬 역할 거절 및 정상경로 테스트 통과, 내부ID 할당 허용과 외부신원 검증 의무가 문서/입력 계약에서 구분됨.
- 현재 두 예약의 역할·단계가 구분되고 수집/이전예약의 일정·활성·지시가 보존됐다는 실제 readback.
- 기존queue/pending입력/운영DB 변경0. 실제 자동 승인 검토에서 등록이 허용됐다는 증거는 이번 격리검증으로 대신하지 않는다. 완벽/운영성공을 미리 주장하지 않는다.

## 이번 단계 검증 결과

- [x] 내부 bandId/외부 musicBrainzId 계약을 문서와 클라이언트 주석에 분리. 기존 pending입력은 변경/재전송하지 않음.
- [x] queue CLI에서 명시적 artist 역할 없이 변경/배치등록 가능 명령을 호출하면 파일·env·네트워크 접근 전에 거절. monitor/status는 lock과 queue bytes도 보존.
- [x] 신규 내부행ID와 외부ID 불변성·false근거/중복거절 및 기존 lease/journal/readback 회귀를 포함해 격리 테스트 57개 통과.
- [x] npm run lint/build 통과. 기존 500kB 초과 번들 경고는 남음.
- [x] 실제 아티스트 예약은 artist/prepare, 감시는 monitor/observe로 갱신 후 peek readback의 prompt 원문 일치 확인. 현재 두 예약의 일정/활성은 유지. 이전 중지2개/별도수집 예약의 prompt·일정·활성·thread 모두 불변.
- [x] 실제queue4558/cloud/active=null/transfer=null 및 SHA 전후불변. 실제 아티스트 등록/승인/queue쓰기/운영DB쓰기/공개ON/발송0.
- [ ] 두 예약의 물리적 채팅 분리: 현재 동일 thread. 예약 도구가 thread/conversation 변경을 지원하지 않아 변경하지 못함. 새예약 생성/기존예약 복제/숨은API로 우회하지 않음.
- [ ] 실제 등록의 자동 승인 검토 통과·receipt/readback: 다음 단계이며 이번 테스트로 완료 처리하지 않음.

단계 판정: 지침·CLI의 논리적 역할 분리와 ID 구분은 검증했다. 물리적 채팅 독립이나 향후 자동 승인 검토의 성공까지 ‘완벽히 해결’됐다고 주장하지 않는다. 아티스트 예약의 prepare 단계는 계속 유지하며, 다음 사용자 재개 지시 전 등록/승인에 들어가지 않는다. 출처 범위 해결과 NOL 자료출처/예매링크 차단 보완도 아직 실행하지 않았다.
