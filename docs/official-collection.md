# 공식 출처 수집과 검수

10/8 계획을 2026-10-07에 진행했다. 실제 주최사 페이지 수집은 확인했고, 원격 후보 업로드와 정기 실행은 아직 하지 않았다.

## 첫 출처 선택

| 출처 | 접근·인증 | 제공 범위와 제약 | 결정 |
| --- | --- | --- | --- |
| [ualive 공연 목록](https://ualive.com/concerts) | 공개 HTML, 별도 로그인·키 없음 | 주최사 공연 제목·장소·회차·예매 링크. 발표일·일반 예매 오픈 시각은 이 경로에서 확인되지 않음 | 첫 경로. 기존 MCR 공식 출처와 연결되며 공개 페이지 수집을 실제 확인 |

2026-10-07 실제 HTTP 확인: 목록·상세·robots.txt 200, 12개 후보, 실패 0. robots는 `/api`, 로그인·사용자 페이지와 JSON 경로를 제외하며 공개 공연 경로를 허용했다. 이는 서비스 제공 범위의 보장이나 별도 이용 계약을 뜻하지 않는다. 수집 전에 robots를 다시 확인하고 공연 경로 제외가 추가되면 중단한다.

## 실행

```sh
npm ci
node scripts/collect-ualive.mjs
```

기본 실행은 공개 출처를 읽고 후보 JSON을 출력한다. 원격 변경은 하지 않는다. 한 번에 최대 50개, 요청 간격 1초, 요청 제한 20초, 리다이렉트 거부. HTML 구조가 바뀌거나 회차가 없으면 실패로 남기며 빈 값으로 기존 공연을 덮어쓰지 않는다. 상세 실패는 나머지 후보와 함께 기록하고 종료 코드 1을 반환한다. 목록·robots 단계 실패는 작업 로그에 남고 업로드하지 않는다.

업로드 전에 `202610080001_ingestion.sql`을 Supabase SQL Editor에서 실행한다. 기존 초기·관리자 마이그레이션이 필요하다. 원격 DB에서는 현재 후보 테이블 조회가 404여서 적용 대기임을 확인했다.

서버 전용 환경변수 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 설정하고 아래 명령을 실행한다. 키는 채팅·소스·VITE 변수에 넣지 않는다.

```sh
node scripts/collect-ualive.mjs --upload
```

서비스 역할 또는 로그인된 관리자만 수집 RPC를 호출할 수 있다. 일반 계정은 후보·실행 기록을 읽거나 수정할 수 없다. 반복 실행은 원문 URL과 정규화 내용 해시로 중복을 합치고, 변경 시 이전 내용·수정 번호를 보존하며 다시 검수 대기로 돌린다. 같은 내용이면 검수 완료/제외 상태를 유지한다. 수집 일시는 발표일로 쓰지 않는다. 원문에 없는 발표일·출연진 매칭·일반 예매 오픈·가격·도시·취소 여부는 검수자가 보완한다. 원문 누락으로 공개 공연을 자동 삭제하거나 취소하지 않는다.

## 정기 실행 설정

`.github/workflows/collect-ualive.yml`은 수동 실행과 6시간 간격 수집을 정의한다. GitHub의 `catalog-ingestion` environment에 위 두 secrets를 설정한다. 아직 푸시·실행·secrets 등록은 하지 않았다. 일정 실행은 기본 브랜치에 workflow가 반영되어야 시작되며 GitHub 실행 지연이 있을 수 있다. 처음에는 workflow_dispatch로 해당 브랜치의 업로드를 확인한다. 환경을 삭제하거나 secrets를 비우면 업로드는 실패한다. 수집을 멈추려면 해당 workflow를 Disable한다.

## 관리자 검수

관리자 화면의 자동 수집 후보에서 원문·수정 번호·이전 내용을 확인하고 `검수 입력에 반영`을 누른다. 같은 공식 URL이 기존 공연에 있으면 기존 공연 ID·발표 확인·라인업·예매 ID·수정 충돌 토큰을 유지한 수정안으로 연다. 다른 URL의 같은 공연이나 밴드 이름은 자동 합치지 않는다. 원문 URL과 기존 목록을 확인하고 중복 후보는 제외한다.

입력 반영은 저장과 별개다. 출처 확인·발표일·밴드 매칭·예매 정보 등을 보완하고 검수/공개 상태로 저장한다. 저장 성공 후 후보를 `검수 완료 표시`한다. 이 표시는 공연 저장이나 공개를 수행하지 않는다. 후보를 읽은 뒤 다른 수집이 수정했다면 완료 표시는 충돌로 거부되므로 다시 불러온다. 자동 수집은 공개·알림 발송을 수행하지 않는다.

## 검증과 남은 작업

- 실제 12개 공개 페이지 수집 성공. 가상 공연을 원격 DB에 등록하지 않았다.
- 로컬 PostgreSQL에서 일반 사용자 차단·관리자 수집·반복 중복·수정 번호·이전 내용·충돌·공개 테이블 미변경 검증.
- 자동 UI 테스트에서 기존 공식 URL의 공연 ID·예매 ID·발표일 보존과 검수 충돌 안내 검증.
- 원격 업로드, GitHub 정기 실행, 실제 관리자 검수·공개와 두 브라우저 반영은 미검증이다. 12개 후보는 12개 검증된 밴드 공연이라는 뜻이 아니다.
