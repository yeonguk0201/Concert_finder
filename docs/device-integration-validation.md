## 준비

## 사용자 검증 보고 · 2026-10-10

위 상태 갱신은 사용자 보고에 근거하며 에이전트가 기기에서 재실행한 결과가 아니다. N01의 약 1분은 체감 관측이며 발송/수신 타임스탬프 측정값이 아니다. 배포 커밋·기기/OS/브라우저 버전은 미제공이다. N02의 테스트 환경과 추가 라인업 원복 여부도 미확인이다. 공식 공개 카탈로그에서 테스트했다면 임의 추가한 Oasis 라인업은 검증된 공식 정보로 원복해야 한다.

첨부한 날짜 입력 오류는 공연 시작일 `2026-11-31`이 존재하지 않는 날짜라 발생한 브라우저 유효성 안내다. 11월은 30일까지다. 정상 날짜 입력으로 확인하며 앱 결함으로 집계하지 않는다.

### N04c 재검증과 기기 관리 추가 보고

사용자가 2시간 전에는 미수신, 1시간 전에는 수신을 확인했다. 30분 전 미수신이라는 첫 보고는 재검증으로 정정했다. 아직 알림을 받은 적 없는 예매 30분 전 일정을 처음 저장하면 ‘예매가 곧 시작된다’는 알림을 받았고, 이미 1시간 전 알림을 받은 같은 일정은 다시 저장해도 중복 발송되지 않는다고 명시 확인했다. 첨부 상세 화면의 티켓 오픈은 10월 10일 16:58이며, 저장 해제 버튼이 표시된다. 저장·발송·수신의 정확한 시각은 미제공이므로 지연 수치를 추정하지 않는다. 과거 예매 미수신은 별도 실제 결과가 아직 없다.

웹·Android·iPhone 등록 후 iPhone만 기기 해제하면 iPhone 미수신, 다시 등록하면 수신된다고 보고했다. 이는 N05 기기 관리 검증이다. 계정 영구 삭제를 수행한 보고는 아니므로 O03/O04는 대기로 유지한다. 다른 등록 기기의 해제 전후 비교 결과도 별도 명시되지는 않았다.

## 로컬 검증 기록 · 2026-10-09

- 계정 삭제 endpoint: 무인증·만료 토큰·계정 불일치·확인 누락·허용하지 않은 메서드 차단, 서버 오류의 비밀정보 미노출 확인.
- 전체 마이그레이션 적용 PostgreSQL 엔진: 계정 삭제 시 찜·일정·동의·기기·발송/시도·계정 신호·관리자 권한 삭제, 타 계정과 카탈로그 유지, 이전 JWT 식별자의 저장 재생성 차단 확인.
- 로컬 앱은 실제 공개 카탈로그를 읽기만 했다. 계정/공연/알림 원격 데이터를 변경하거나 실제 계정을 삭제하지 않았다.
- 320px·390px·1280px에서 문서 가로 넘침 없음, 표시된 조작 버튼/입력/선택/안내 펼치기 높이 44px 이상 확인. 320px 로그인·공연 상세, 390px 개인정보 안내, 데스크톱 화면을 시각 점검했다.
- 본문 건너뛰기의 main 포커스, 키보드 상세 열기·Shift+Tab의 dialog 내 포커스 유지, Escape 닫기와 원래 버튼 복귀, 키보드 안내 펼치기를 확인했다. 실제 휴대폰 키보드·화면 읽기 도구는 미검증이다.
- 개발 중 hook 추가의 HMR 오류가 이전 탭에 남아 있었으나, 최종 새 탭의 로그인 화면/공개 카탈로그 로딩에서 콘솔 오류·경고 없음 확인.

## 운영 계정 삭제 사용자 확인 · 2026-10-10

사용자가 삭제 기능 배포 후 ‘계정 삭제도 된다’고 확인했다. 실제 계정 삭제의 사용자 흐름 성공으로 기록한다. 삭제한 계정·기기·정확한 시각은 미제공이며 서버 Auth/개인 데이터 행을 에이전트가 직접 조회한 결과는 아니다. 추가로 사용자가 삭제 후 알림이 오지 않고 같은 이메일로 재가입하면 목록이 비어 있다고 확인했다. 알림 미수신의 관측 시간과 서버 발송 기록은 미제공이므로 사용자 관측 결과로 기록한다. 타 계정 유지와 O04의 다른 기기 접근/쓰기 차단은 별도 확인이 필요하다. 기존 로컬 cascade 검증은 유지하되 실제 서버 데이터 제거 확인과 구분한다.


### O04 다른 기기 세션 결함 · 2026-10-10

사용자는 삭제 전에 로그인해 둔 다른 기기에서 새로고침해도 ‘계정으로 로그인됨’이 남는다고 보고했다. 공연 알림·푸시 테스트 동의를 체크하면 수신 동의 저장이 오류 코드 23503으로 거부됐다. 이는 해당 설정 쓰기의 차단 근거이며 모든 접근·쓰기의 실기기 검증 완료로 확대하지 않는다.

브라우저 세션 복구만 사용하던 로그인 상태를 Auth 서버의 getUser로 재확인하도록 수정한다. 새로고침·창 포커스·앱 복귀와 알림/목록 저장의 외래키 오류 시 계정 상태를 확인하며, 계정 없음·인증 무효가 확인되면 로컬 로그아웃과 재로그인 안내를 제공한다. 네트워크 장애와 계정이 유효한 일반 외래키 오류는 로그아웃 근거로 사용하지 않는다. 수정 배포 후 다른 기기에서 재검증해야 한다.

수정 검증: lint·build 통과, Node 26개·UI 50개 통과. 알림 RPC의 23503 거부부터 Auth 재확인·로그아웃까지 회귀 검사했고, 서버 확인 중 계정 전환·네트워크 장애·정상 계정의 일반 외래키 오류도 검사했다. 마지막 테스트 보강 후 관련 20개를 재실행해 통과했다. build 청크 크기 경고는 유지된다. 실제 다른 기기 재검증은 배포 후 사용자 확인 대기다.
